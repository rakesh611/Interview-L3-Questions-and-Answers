# `sysctl` Command in Linux

## 1. What is `sysctl`?

`sysctl` is a Linux command used to **view and modify kernel runtime parameters**.

These parameters control many operating-system behaviors, including:

- Networking
- Virtual memory
- File-system limits
- Process limits
- Kernel security
- TCP/IP behavior
- Shared memory
- Swapping
- Packet forwarding
- Performance tuning

Most kernel parameters exposed through `sysctl` are stored in the virtual file system:

```text
/proc/sys/
```

For example:

```text
/proc/sys/net/ipv4/ip_forward
```

is represented by `sysctl` as:

```text
net.ipv4.ip_forward
```

The slash `/` in `/proc/sys/` is replaced with a dot `.` in the `sysctl` parameter name.

---

## 2. Syntax

```bash
sysctl [options] [variable[=value]]
```

Examples:

```bash
sysctl kernel.hostname
sysctl net.ipv4.ip_forward
sudo sysctl -w net.ipv4.ip_forward=1
```

---

## 3. Important Files

### 3.1 Runtime kernel interface

```text
/proc/sys/
```

Changes made directly under `/proc/sys/` or with `sysctl -w` normally remain active only until the next reboot.

### 3.2 Main persistent configuration file

```text
/etc/sysctl.conf
```

### 3.3 Drop-in configuration directories

Modern Linux systems commonly use:

```text
/etc/sysctl.d/*.conf
/run/sysctl.d/*.conf
/usr/local/lib/sysctl.d/*.conf
/usr/lib/sysctl.d/*.conf
/lib/sysctl.d/*.conf
```

For administrator-managed settings, the preferred location is usually:

```text
/etc/sysctl.d/99-custom.conf
```

Example:

```bash
sudo vi /etc/sysctl.d/99-custom.conf
```

```ini
net.ipv4.ip_forward = 1
vm.swappiness = 10
fs.file-max = 2097152
```

Load the configuration:

```bash
sudo sysctl --system
```

# 4. Important `sysctl` Commands

## 4.1 Display all available kernel parameters

```bash
sysctl -a
```

Example:

```bash
sysctl -a | less
```

Search networking parameters:

```bash
sysctl -a | grep '^net.ipv4'
```

Search memory-related parameters:

```bash
sysctl -a | grep '^vm\.'
```

> `sysctl -a` may display warnings for parameters that cannot be read due to permissions or kernel restrictions.

---

## 4.2 Display one kernel parameter

```bash
sysctl parameter_name
```

Example:

```bash
sysctl vm.swappiness
```

Possible output:

```text
vm.swappiness = 60
```

Another example:

```bash
sysctl net.ipv4.ip_forward
```

Possible output:

```text
net.ipv4.ip_forward = 0
```

---

## 4.3 Display only the value

Use `-n`:

```bash
sysctl -n vm.swappiness
```

Output:

```text
60
```

This is useful in shell scripts.

Example:

```bash
current_value=$(sysctl -n vm.swappiness)
echo "Current swappiness: $current_value"
```

---

## 4.4 Write or modify a runtime parameter

Use `-w`:

```bash
sudo sysctl -w parameter=value
```

Example:

```bash
sudo sysctl -w vm.swappiness=10
```

Output:

```text
vm.swappiness = 10
```

Verify:

```bash
sysctl vm.swappiness
```

> A change made with `sysctl -w` is normally temporary and is lost after reboot unless saved in a configuration file.

---

## 4.5 Load settings from `/etc/sysctl.conf`

```bash
sudo sysctl -p
```

By default, `-p` reads:

```text
/etc/sysctl.conf
```

Example:

```bash
echo 'vm.swappiness = 10' | sudo tee -a /etc/sysctl.conf
sudo sysctl -p
```

---

## 4.6 Load settings from a specific file

```bash
sudo sysctl -p /path/to/file.conf
```

Example:

```bash
sudo sysctl -p /etc/sysctl.d/99-custom.conf
```

This command applies settings only from the specified file.

---

## 4.7 Load all sysctl configuration files

```bash
sudo sysctl --system
```

This reads configuration files from the standard sysctl directories.

Typical use:

```bash
sudo sysctl --system
```

This is generally preferred after creating or modifying a file under:

```text
/etc/sysctl.d/
```

---

## 4.8 Ignore unknown or invalid parameters

Use `-e`:

```bash
sudo sysctl -e -p /etc/sysctl.d/99-custom.conf
```

The command continues even when a parameter does not exist.

This can be useful when the same configuration is deployed across systems with different kernels.

---

## 4.9 Display parameter names without values

Use `-N`:

```bash
sysctl -N
```

Example:

```bash
sysctl -N | grep '^net.ipv4'
```

---

## 4.10 Display values without parameter names

Use `-n`:

```bash
sysctl -n kernel.hostname
```

Example output:

```text
server01.example.com
```

---

## 4.11 Read a parameter directly from `/proc/sys`

The following two commands provide equivalent information:

```bash
sysctl net.ipv4.ip_forward
```

```bash
cat /proc/sys/net/ipv4/ip_forward
```

To change it directly:

```bash
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward
```

The preferred method is:

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

because it is clearer and safer for administration and scripting.

# 5. Common `sysctl` Parameters

## 5.1 Enable IPv4 packet forwarding

Check:

```bash
sysctl net.ipv4.ip_forward
```

Enable temporarily:

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

Make persistent:

```bash
cat <<'EOF' | sudo tee /etc/sysctl.d/90-ip-forward.conf
net.ipv4.ip_forward = 1
EOF

sudo sysctl --system
```

Use cases:

- Linux router
- NAT gateway
- Kubernetes node
- VPN gateway
- Container host

Security note: Do not enable forwarding unless the server is intended to route traffic. Review firewall rules after enabling it.

---

## 5.2 Control swapping behavior

Check:

```bash
sysctl vm.swappiness
```

Set temporarily:

```bash
sudo sysctl -w vm.swappiness=10
```

Make persistent:

```bash
echo 'vm.swappiness = 10' | sudo tee /etc/sysctl.d/90-memory.conf
sudo sysctl --system
```

General interpretation:

- Higher values make the kernel more willing to swap.
- Lower values reduce swapping preference.
- A value of `0` does not always mean swap is completely disabled.
- The best value depends on the workload.

For database and latency-sensitive workloads, administrators commonly test lower values, but the change should be validated with real workload data.

---

## 5.3 Configure file-handle limit

Check:

```bash
sysctl fs.file-max
```

Set temporarily:

```bash
sudo sysctl -w fs.file-max=2097152
```

Make persistent:

```bash
echo 'fs.file-max = 2097152' | sudo tee /etc/sysctl.d/90-file-limits.conf
sudo sysctl --system
```

Check current kernel file-handle usage:

```bash
cat /proc/sys/fs/file-nr
```

Example output:

```text
12288  0  2097152
```

Important: `fs.file-max` is a system-wide kernel limit. Per-user and per-service limits are also controlled by:

```text
/etc/security/limits.conf
/etc/security/limits.d/*.conf
systemd LimitNOFILE=
```

---

## 5.4 Configure maximum memory-map areas

Check:

```bash
sysctl vm.max_map_count
```

Set temporarily:

```bash
sudo sysctl -w vm.max_map_count=262144
```

Make persistent:

```bash
echo 'vm.max_map_count = 262144' | sudo tee /etc/sysctl.d/90-vm-map-count.conf
sudo sysctl --system
```

This parameter is commonly important for applications such as:

- Elasticsearch
- OpenSearch
- Large Java applications
- Database systems
- Applications using many memory mappings

---

## 5.5 Configure shared memory maximum

Check:

```bash
sysctl kernel.shmmax
sysctl kernel.shmall
```

Example temporary change:

```bash
sudo sysctl -w kernel.shmmax=68719476736
```

These parameters can affect database workloads that use System V shared memory.

Do not copy values blindly. Calculate them according to:

- Physical RAM
- Database configuration
- Page size
- Application requirements
- Vendor recommendations

---

## 5.6 Control ICMP echo responses

Check:

```bash
sysctl net.ipv4.icmp_echo_ignore_all
```

Disable ping replies temporarily:

```bash
sudo sysctl -w net.ipv4.icmp_echo_ignore_all=1
```

Enable ping replies:

```bash
sudo sysctl -w net.ipv4.icmp_echo_ignore_all=0
```

Disabling ICMP echo is not a complete security control and can make troubleshooting harder.

---

## 5.7 Enable SYN cookies

Check:

```bash
sysctl net.ipv4.tcp_syncookies
```

Enable:

```bash
sudo sysctl -w net.ipv4.tcp_syncookies=1
```

Make persistent:

```bash
echo 'net.ipv4.tcp_syncookies = 1' | sudo tee /etc/sysctl.d/90-network-security.conf
sudo sysctl --system
```

SYN cookies can help protect against some SYN flood conditions, but they are not a replacement for firewalling, rate limiting, or upstream DDoS protection.

---

## 5.8 Configure TCP listen backlog

Check:

```bash
sysctl net.core.somaxconn
```

Set temporarily:

```bash
sudo sysctl -w net.core.somaxconn=4096
```

Make persistent:

```bash
echo 'net.core.somaxconn = 4096' | sudo tee /etc/sysctl.d/90-network-performance.conf
sudo sysctl --system
```

Application-level backlog settings must also be reviewed. Increasing the kernel maximum alone may not improve performance.

---

## 5.9 Configure dirty-page writeback

Check:

```bash
sysctl vm.dirty_ratio
sysctl vm.dirty_background_ratio
```

Example:

```bash
sudo sysctl -w vm.dirty_background_ratio=5
sudo sysctl -w vm.dirty_ratio=15
```

These values control how much memory can contain modified, not-yet-written pages.

Incorrect tuning can cause:

- Long write stalls
- Burst-write latency
- Storage saturation
- Application pauses
- Excessive writeback activity

Always benchmark before changing production values.

---

## 5.10 Configure reverse-path filtering

Check:

```bash
sysctl net.ipv4.conf.all.rp_filter
sysctl net.ipv4.conf.default.rp_filter
```

Example:

```bash
sudo sysctl -w net.ipv4.conf.all.rp_filter=1
```

Reverse-path filtering can help reduce IP spoofing, but strict settings may cause problems in:

- Asymmetric routing
- Multi-homed servers
- Policy routing
- Complex VPN environments
- Kubernetes or OpenShift networking

---

# 6. Creating a Persistent `sysctl` Configuration

Create a dedicated configuration file:

```bash
sudo vi /etc/sysctl.d/99-corporate-tuning.conf
```

Example content:

```ini
# Enable IPv4 packet forwarding
net.ipv4.ip_forward = 1

# Reduce swap preference
vm.swappiness = 10

# Increase system-wide file-handle limit
fs.file-max = 2097152

# Increase maximum number of memory-map areas
vm.max_map_count = 262144

# Increase TCP listen backlog
net.core.somaxconn = 4096
```

Apply:

```bash
sudo sysctl --system
```

Verify:

```bash
sysctl net.ipv4.ip_forward
sysctl vm.swappiness
sysctl fs.file-max
sysctl vm.max_map_count
sysctl net.core.somaxconn
```

# 7. Safe Production Change Procedure

A production administrator should not change kernel parameters without evidence.

## Step 1: Capture the current value

```bash
sysctl vm.swappiness
```

## Step 2: Record the existing configuration source

```bash
grep -R --line-number --fixed-strings \
'vm.swappiness' \
/etc/sysctl.conf /etc/sysctl.d /usr/lib/sysctl.d 2>/dev/null
```

## Step 3: Apply the change temporarily

```bash
sudo sysctl -w vm.swappiness=10
```

## Step 4: Monitor the workload

Useful commands:

```bash
vmstat 1
sar -W 1
free -h
pidstat -r 1
```

## Step 5: Make the change persistent only after validation

```bash
echo 'vm.swappiness = 10' | sudo tee /etc/sysctl.d/99-memory-tuning.conf
sudo sysctl --system
```

## Step 6: Prepare rollback

```bash
sudo sysctl -w vm.swappiness=60
sudo rm -f /etc/sysctl.d/99-memory-tuning.conf
sudo sysctl --system
```

Replace `60` with the original value captured before the change.

# 8. Troubleshooting `sysctl`

## 8.1 Error: Permission denied

Example:

```text
sysctl: permission denied on key "net.ipv4.ip_forward"
```

Possible causes:

- Command not executed as root
- Container restrictions
- Read-only `/proc/sys`
- Security policy
- Kernel lockdown
- Parameter is not writable

Try:

```bash
sudo sysctl -w net.ipv4.ip_forward=1
```

In a container, the host or container runtime may need to allow the parameter.

---

## 8.2 Error: Cannot stat `/proc/sys/...`

Example:

```text
sysctl: cannot stat /proc/sys/net/ipv4/example: No such file or directory
```

Possible causes:

- Typing error
- Parameter not supported by the running kernel
- Required kernel module is not loaded
- Parameter exists only on a different kernel version
- Configuration copied from another operating system

Check:

```bash
sysctl -a | grep parameter_name
```

---

## 8.3 Setting changes but returns after reboot

Cause:

```bash
sudo sysctl -w parameter=value
```

changes only the runtime value.

Solution:

```bash
echo 'parameter = value' | sudo tee /etc/sysctl.d/99-custom.conf
sudo sysctl --system
```

---

## 8.4 Persistent value is not applied

Check for conflicting configuration:

```bash
grep -R --line-number \
'parameter_name' \
/etc/sysctl.conf \
/etc/sysctl.d \
/run/sysctl.d \
/usr/local/lib/sysctl.d \
/usr/lib/sysctl.d \
/lib/sysctl.d 2>/dev/null
```

Reload all files:

```bash
sudo sysctl --system
```

Check boot logs:

```bash
journalctl -b | grep -i sysctl
```

Check the systemd sysctl service:

```bash
systemctl status systemd-sysctl.service
```

---

## 8.5 Invalid argument

Example:

```text
sysctl: setting key "parameter": Invalid argument
```

Possible causes:

- Value is outside the permitted range
- Parameter expects a different format
- Kernel feature does not support the requested value
- Incorrect units

Check documentation and current value:

```bash
sysctl parameter_name
```

# 9. Useful Command Examples

## List all TCP parameters

```bash
sysctl -a | grep '^net.ipv4.tcp'
```

## List all IPv4 forwarding parameters

```bash
sysctl -a | grep 'forwarding'
```

## Save the current sysctl configuration

```bash
sysctl -a > sysctl-backup-$(date +%F).txt
```

## Compare before and after values

```bash
sysctl -a | sort > /tmp/sysctl-before.txt

# Apply intended changes here

sysctl -a | sort > /tmp/sysctl-after.txt
diff -u /tmp/sysctl-before.txt /tmp/sysctl-after.txt
```

## Find a parameter by keyword

```bash
sysctl -a 2>/dev/null | grep -i backlog
```

## Check whether IP forwarding is enabled in a script

```bash
if [[ "$(sysctl -n net.ipv4.ip_forward)" -eq 1 ]]; then
    echo "IPv4 forwarding is enabled"
else
    echo "IPv4 forwarding is disabled"
fi
```

# 10. Example Validation Script

Create:

```bash
vi check-sysctl.sh
```

Content:

```bash
#!/usr/bin/env bash

set -u

parameters=(
    "net.ipv4.ip_forward"
    "vm.swappiness"
    "fs.file-max"
    "vm.max_map_count"
    "net.core.somaxconn"
)

for parameter in "${parameters[@]}"; do
    if value=$(sysctl -n "$parameter" 2>/dev/null); then
        printf '%-35s %s\n' "$parameter" "$value"
    else
        printf '%-35s %s\n' "$parameter" "NOT AVAILABLE"
    fi
done
```

Make executable:

```bash
chmod +x check-sysctl.sh
```

Run:

```bash
./check-sysctl.sh
```

# 12. Important Notes for RHEL, Rocky Linux, AlmaLinux, and CentOS Stream

On systemd-based distributions, persistent sysctl settings are generally loaded by:

```text
systemd-sysctl.service
```

Check its status:

```bash
systemctl status systemd-sysctl.service
```

Reload sysctl configuration:

```bash
sudo systemctl restart systemd-sysctl.service
```

or:

```bash
sudo sysctl --system
```

Administrator-created tuning should normally be placed in:

```text
/etc/sysctl.d/
```

Avoid directly editing vendor files under:

```text
/usr/lib/sysctl.d/
```

because package updates may overwrite them.

# 13. `sysctl` Command Summary

| Command | Purpose |
|---|---|
| `sysctl -a` | Display all available parameters |
| `sysctl parameter` | Display one parameter |
| `sysctl -n parameter` | Display only the value |
| `sudo sysctl -w parameter=value` | Change a runtime value |
| `sudo sysctl -p` | Load `/etc/sysctl.conf` |
| `sudo sysctl -p file.conf` | Load a specific file |
| `sudo sysctl --system` | Load all standard sysctl configuration files |
| `sysctl -N` | Display parameter names |
| `sudo sysctl -e -p file.conf` | Ignore unknown parameters while loading |
| `cat /proc/sys/path` | Read the equivalent `/proc/sys` value |

---

# 14. Best Practices

1. Capture the original value before changing it.
2. Test changes temporarily using `sysctl -w`.
3. Monitor workload performance after every change.
4. Store custom persistent settings in `/etc/sysctl.d/`.
5. Use meaningful filenames such as `99-network-tuning.conf`.
6. Do not blindly copy internet tuning values.
7. Maintain a rollback procedure.
8. Use configuration management such as Ansible for production systems.
9. Check for duplicate or conflicting parameter definitions.
10. Document the reason, owner, date, and evidence for every production tuning change.
