# Journalctl Command Guide for Linux

## 1. What is `journalctl`?

`journalctl` is a command-line utility used to view and analyze logs collected by **systemd-journald**.

On modern Linux distributions such as:

- Red Hat Enterprise Linux
- Rocky Linux
- AlmaLinux
- Fedora
- Ubuntu
- Debian
- SUSE Linux Enterprise

the `systemd-journald` service collects logs from the kernel, system services, applications, boot process, and standard output/error of services managed by `systemd`.

The `journalctl` command is used to query those logs.

---

## 2. Important Components

### systemd-journald

`systemd-journald` is the logging daemon responsible for collecting system logs.

Check its status:

```bash
systemctl status systemd-journald
```

Example:

```text
● systemd-journald.service - Journal Service
     Loaded: loaded
     Active: active (running)
```

### journalctl

`journalctl` is the client command used to read the logs stored by `systemd-journald`.

Basic command:

```bash
journalctl
```

This displays all available journal entries, starting with the oldest logs.

---

## 3. Why `journalctl` is Important

`journalctl` helps Linux administrators troubleshoot:

- System boot failures
- Service startup failures
- Kernel errors
- Disk and filesystem problems
- Network issues
- Authentication failures
- SELinux-related failures
- Out-of-memory events
- Unexpected reboots
- Application crashes
- Hardware problems
- Scheduled task failures
- Container and virtualization problems

# Important `journalctl` Commands

## 4. Display All Journal Logs

```bash
journalctl
```

Example:

```bash
journalctl
```

Use arrow keys, Page Up, and Page Down to navigate.

Press:

```text
q
```

to exit.

---

## 5. Display Logs Without a Pager

```bash
journalctl --no-pager
```

Example:

```bash
journalctl --no-pager
```

This prints logs directly to the terminal without opening the `less` pager.

Useful in scripts:

```bash
journalctl --no-pager > /tmp/all-journal-logs.txt
```

---

## 6. Show the Most Recent Logs

```bash
journalctl -e
```

The `-e` option jumps directly to the end of the journal.

Example:

```bash
journalctl -e
```

This is useful when you want to inspect the latest system events.

---

## 7. Follow Logs in Real Time

```bash
journalctl -f
```

This works similarly to:

```bash
tail -f /var/log/messages
```

Example:

```bash
journalctl -f
```

While this command is running, new journal entries appear in real time.

Stop it with:

```text
Ctrl+C
```

---

## 8. Show a Specific Number of Recent Entries

```bash
journalctl -n NUMBER
```

Example: show the last 20 log entries:

```bash
journalctl -n 20
```

Show the last 100 entries:

```bash
journalctl -n 100
```

Follow logs after displaying the last 50 entries:

```bash
journalctl -n 50 -f
```

# Boot Logs

## 13. Show Logs from the Current Boot

```bash
journalctl -b
```

Example:

```bash
journalctl -b
```

This displays only logs generated after the current boot.

---

## 14. List Available Boots

```bash
journalctl --list-boots
```

Example output:

```text
-2  8f9a7c4d... Sun 2026-07-26 08:10:10 IST—Sun 2026-07-26 16:20:32 IST
-1  721b5e1a... Sun 2026-07-26 18:27:10 IST—Mon 2026-07-27 10:10:20 IST
 0  2c83d9f2... Mon 2026-07-27 10:15:30 IST—Mon 2026-07-27 14:30:40 IST
```

Meaning:

- `0` means the current boot
- `-1` means the previous boot
- `-2` means two boots ago

# Priority-Based Filtering

## 20. Journal Priority Levels

Linux journal priorities are:

| Number | Priority | Meaning |
|---:|---|---|
| 0 | emerg | System is unusable |
| 1 | alert | Immediate action required |
| 2 | crit | Critical condition |
| 3 | err | Error condition |
| 4 | warning | Warning condition |
| 5 | notice | Normal but significant event |
| 6 | info | Informational message |
| 7 | debug | Debug message |

---

# Disk Usage and Journal Maintenance

## 43. Check Journal Disk Usage

```bash
journalctl --disk-usage
```

Example output:

```text
Archived and active journals take up 1.8G in the file system.
```

---

## 44. Remove Old Logs Based on Size

```bash
journalctl --vacuum-size=500M
```

This removes archived journal files until journal disk usage falls below approximately 500 MB.

Example:

```bash
sudo journalctl --vacuum-size=1G
```

---

## 45. Remove Old Logs Based on Age

```bash
journalctl --vacuum-time=7d
```

Examples:

```bash
sudo journalctl --vacuum-time=7d
```

```bash
sudo journalctl --vacuum-time=30d
```

Before vacuuming, rotate the active journal:

```bash
sudo journalctl --rotate
sudo journalctl --vacuum-time=7d
```

---

## 46. Limit the Number of Journal Files


Example:

# Persistent Journal Configuration

## 61. Check Whether Persistent Storage Exists

```bash
ls -ld /var/log/journal
```

Persistent logs are normally stored under:

```text
/var/log/journal/
```

Volatile logs are normally stored under:

```text
/run/log/journal/
```

Logs under `/run` are lost after reboot.

---

## 62. Enable Persistent Journal Storage

Create the directory:

```bash
sudo mkdir -p /var/log/journal
```

Apply the expected permissions:

```bash
sudo systemd-tmpfiles --create --prefix /var/log/journal
```

Restart journald:

```bash
sudo systemctl restart systemd-journald
```

Verify:

```bash
journalctl --list-boots
```

---

## 63. Configure Journald Retention

Configuration file:

```text
/etc/systemd/journald.conf
```

Example configuration:

```ini
[Journal]
Storage=persistent
SystemMaxUse=1G
SystemKeepFree=2G
SystemMaxFileSize=100M
MaxRetentionSec=30day
Compress=yes
```

Restart the service after changing the configuration:

```bash
sudo systemctl restart systemd-journald
```

Important parameters:

| Parameter | Purpose |
|---|---|
| `Storage=persistent` | Stores logs under `/var/log/journal` |
| `SystemMaxUse=` | Maximum total persistent journal size |
| `SystemKeepFree=` | Disk space journald should leave free |
| `SystemMaxFileSize=` | Maximum size of each journal file |
| `MaxRetentionSec=` | Maximum retention period |
| `Compress=yes` | Compresses older journal data |

# Production Troubleshooting Workflow

## 73. Recommended Incident Workflow

### Step 1: Confirm system time

```bash
date
timedatectl
```

Correct timestamps are necessary before analyzing logs.

### Step 2: Check failed services

```bash
systemctl --failed
```

### Step 3: Check high-priority current-boot messages

```bash
journalctl -b -p warning
```

### Step 4: Check the affected service

```bash
journalctl -u SERVICE_NAME -b
```

### Step 5: Narrow the incident time

```bash
journalctl --since "START_TIME" --until "END_TIME"
```

### Step 6: Check kernel events

```bash
journalctl -k -b
```

### Step 7: Search common failure terms

```bash
journalctl -b \
  | grep -Ei "error|failed|timeout|reset|oom|panic|segfault"
```

### Step 8: Export evidence

```bash
journalctl -b --no-pager > /tmp/current-boot-journal.log
```

### Step 9: Preserve service-specific evidence

```bash
journalctl -u SERVICE_NAME -b --no-pager \
  > /tmp/service-journal.log
```

For XFS:

```bash
journalctl -k | grep -Ei "xfs|metadata I/O error|corruption"
```

For EXT4:

```bash
journalctl -k | grep -Ei "ext4-fs error|remounting filesystem read-only"
```

---

# Important Notes and Limitations

## 79. Root Permission

A normal user may not be able to see all system logs.

Use:

```bash
sudo journalctl
```

Users in groups such as `systemd-journal`, `adm`, or `wheel` may have broader access depending on the distribution.

---

## 80. Journal Logs May Be Volatile

When logs are stored under:

```text
/run/log/journal
```

they are lost during reboot.

For previous-boot troubleshooting, enable persistent storage under:

```text
/var/log/journal
```

---

## 81. `journalctl` and Traditional Log Files

Depending on the distribution and rsyslog configuration, messages may also appear in:

```text
/var/log/messages
/var/log/syslog
/var/log/secure
/var/log/auth.log
/var/log/cron
```

On RHEL-like systems:

```text
/var/log/messages
/var/log/secure
```

are common.

On Debian/Ubuntu-like systems:

```text
/var/log/syslog
/var/log/auth.log
```

are common.

`journalctl` often provides richer metadata than traditional text logs.

# Final Summary

`journalctl` is the primary command for querying logs generated and collected by `systemd-journald`.

For most Linux incidents, begin with:

```bash
systemctl --failed
journalctl -b -p warning
journalctl -u SERVICE_NAME -b
journalctl -k -b
```

For an unexpected reboot, use:

```bash
journalctl --list-boots
journalctl -b -1 -e
journalctl -k -b -1 -p warning
```

For a failed service, use:

```bash
systemctl status SERVICE_NAME
journalctl -u SERVICE_NAME -n 100
journalctl -u SERVICE_NAME -f
```

For known incident times, always narrow the logs:

```bash
journalctl \
  --since "YYYY-MM-DD HH:MM:SS" \
  --until "YYYY-MM-DD HH:MM:SS"
```

This reduces noise and makes root-cause analysis faster and more reliable.
