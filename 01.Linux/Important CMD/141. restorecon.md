# 141. restorecon

> **Scope:** Corporate/L3 Linux administration, incident troubleshooting, safe change execution, and interview preparation.

## 1. What it is

`restorecon` applies the SELinux context expected by the active file-context policy to files and directories. It is the preferred way to correct persistent-path labeling after defining any required custom mapping.

## 2. Production importance

- Provides a repeatable method for diagnosing or controlling the relevant Linux subsystem.
- Produces evidence suitable for incident timelines, change records, problem management, and audit review.
- Encourages before-and-after measurement instead of unverified tuning or repair.
- Separates command success from actual application availability, security, and data integrity.

## 3. Package or kernel interface

- **Primary package/interface:** policycoreutils
- Check availability and installed version before relying on an option:

```bash
command -v restorecon 2>/dev/null || true
rpm -q PACKAGE_NAME 2>/dev/null || true
COMMAND --version 2>/dev/null || COMMAND --help
```

## 4. Core concepts

- Expected contexts come from policy file-context definitions and local `semanage fcontext` customizations.
- `restorecon` differs from `chcon`, which directly sets a label that may be overwritten later.
- Preview mode prevents accidental broad relabeling.
- Recursive operations can be expensive on large directory trees.
- Relabeling fixes label mismatches, not arbitrary policy denials.
- Moved files can retain an old directory's label, while newly created files usually inherit policy through creation behavior.

## 5. Important commands

| Command | Purpose | Risk |
|---|---|---|
| `matchpathcon -V /srv/web/index.html` | Verify current label against policy. | Read-only |
| `restorecon -n -v /srv/web/index.html` | Preview a label correction. | Read-only |
| `sudo restorecon -v /srv/web/index.html` | Restore one file's context. | SELinux label change |
| `sudo restorecon -Rv /srv/web` | Restore contexts recursively. | Recursive SELinux label change |
| `sudo restorecon -nRv /srv/web` | Preview a recursive relabel. | Read-only |
| `sudo restorecon -e /srv/web/cache -Rv /srv/web` | Exclude a subtree. | Recursive SELinux label change |
| `sudo semanage fcontext -a -t httpd_sys_content_t '/srv/web(/.*)?'` | Create a persistent custom mapping. | SELinux policy configuration change |
| `sudo restorecon -Rv /srv/web` | Apply the custom mapping. | Recursive SELinux label change |
| `ls -lZd /srv/web /srv/web/index.html` | Display current labels. | Read-only |
| `semanage fcontext -l \| grep -F '/srv/web'` | Verify local policy mapping. | Read-only |
| `ausearch -m AVC -ts recent -i` | Search recent denials. | Read-only |
| `sudo restorecon -Rvv /srv/web` | Use extra verbosity for controlled troubleshooting. | Recursive SELinux label change |

## 7. Output interpretation

- Verbose output reports files whose labels are changed.
- A clean preview means current labels match the expected policy.
- Repeated mismatch after relabel can point to unsupported xattrs, read-only media, overlay behavior, or another tool changing labels.
- The SELinux type is usually the key component for service access.
- Correct labels plus continued AVCs require policy, boolean, domain, and application analysis.

## 8. Corporate/L3 troubleshooting workflow

1. **Confirm impact:** Record affected applications, users, start time, error rate, latency, and business severity.
2. **Identify scope:** Determine whether the issue is host-wide, process-specific, filesystem-specific, network-path-specific, or limited to one namespace.
3. **Preserve evidence:** Save logs, configuration, counters, command output, package versions, and timestamps before changing state.
4. **Establish ownership:** Identify whether systemd, NetworkManager, firewalld, TuneD, udev, a backup scheduler, configuration management, or the application owns the setting.
5. **Use read-only inspection first:** Confirm the hypothesis with at least two independent evidence sources.
6. **Control the test:** Make only one bounded change and define the rollback command in advance.
7. **Measure service behavior:** Validate latency, throughput, errors, data consistency, authentication, and client experience.
8. **Persist correctly:** Apply successful changes through the supported configuration source rather than an ad hoc runtime command.
9. **Close the incident:** Document root cause, contributing conditions, corrective action, monitoring, and prevention.

## 9. Production cautions

- Preview broad operations.
- Define persistent custom mappings before applying labels to nonstandard service paths.
- Do not use recursive relabeling as a substitute for identifying the affected path.
- Do not disable SELinux to avoid fixing a labeling or policy problem.
- Replace all example users, paths, devices, addresses, ports, repositories, and services only after validation.
- Keep console or out-of-band access for firewall, bootloader, storage, authentication, and network changes.
- Back up data and configuration before destructive, recursive, or boot-critical commands.
