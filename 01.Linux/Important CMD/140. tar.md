# 140. tar

> **Scope:** Corporate/L3 Linux administration, incident troubleshooting, safe change execution, and interview preparation.

## 1. What it is

`tar` creates, lists, extracts, compares, and updates archive streams. GNU tar can preserve permissions, ownership, ACLs, extended attributes, SELinux contexts, hard links, sparse files, and several compression formats.

## 2. Production importance

- Provides a repeatable method for diagnosing or controlling the relevant Linux subsystem.
- Produces evidence suitable for incident timelines, change records, problem management, and audit review.
- Encourages before-and-after measurement instead of unverified tuning or repair.
- Separates command success from actual application availability, security, and data integrity.

## 3. Package or kernel interface

- **Primary package/interface:** tar
- Check availability and installed version before relying on an option:

```bash
command -v tar 2>/dev/null || true
rpm -q PACKAGE_NAME 2>/dev/null || true
COMMAND --version 2>/dev/null || COMMAND --help
```

## 4. Core concepts

- An archive is not automatically a complete backup unless required metadata is preserved.
- Absolute paths and `..` components create extraction risk.
- Compression is separate from archive structure.
- Numeric ownership is important when restoring across systems with different name services.
- Sparse files require appropriate options to avoid expansion.
- Incremental archives have special state files and restore procedures.

## 5. Important commands

| Command | Purpose | Risk |
|---|---|---|
| `tar -cvf archive.tar /etc/myapp` | Create an uncompressed archive. | Archive creation |
| `tar -czvf archive.tar.gz /etc/myapp` | Create a gzip-compressed archive. | Archive creation |
| `tar -cJvf archive.tar.xz /etc/myapp` | Create an xz-compressed archive. | Archive creation |
| `tar -tvf archive.tar` | List archive contents. | Read-only |
| `tar -xvf archive.tar -C /restore` | Extract into a selected directory. | File restoration |
| `tar -xvf archive.tar path/inside/archive` | Extract one member. | File restoration |
| `tar --xattrs --acls --selinux --numeric-owner -cpf backup.tar /srv/data` | Preserve Linux security metadata. | Backup creation |
| `sudo tar --xattrs --acls --selinux --numeric-owner -xpf backup.tar -C /restore` | Restore preserved metadata. | Privileged restoration |
| `tar --exclude='*.tmp' --exclude-cache-all -czf app.tar.gz /srv/app` | Exclude selected content. | Read-only |
| `tar --sparse -cpf vm-images.tar /var/lib/libvirt/images` | Preserve sparse files. | Large archive creation |
| `tar -df archive.tar` | Compare archive members with filesystem files. | Read-only |
| `tar -cf - /data \| ssh backuphost 'cat > data.tar'` | Stream an archive over SSH. | Network backup transfer |
| `tar --listed-incremental=/var/lib/backup/data.snar -czf data-inc.tar.gz /data` | Create a GNU incremental archive. | Stateful backup creation |

## 7. Output interpretation

- Verbose prefixes and member names show what was archived or restored.
- Warnings about removing leading `/` are a safety normalization.
- Differences during `-d` can include size, time, mode, owner, and content depending on type.
- An archive can list correctly but still be corrupt later; verify and test extraction.
- Compression ratio is not proof of completeness.

## 8. Corporate/L3 troubleshooting workflow

1. **Confirm impact:** Record affected applications, users, start time, error rate, latency, and business severity.
2. **Identify scope:** Determine whether the issue is host-wide, process-specific, filesystem-specific, network-path-specific, or limited to one namespace.
3. **Preserve evidence:** Save logs, configuration, counters, command output, package versions, and timestamps before changing state.
4. **Establish ownership:** Identify whether systemd, NetworkManager, firewalld, TuneD, udev, a backup scheduler, configuration management, or the application owns the setting.
5. **Use read-only inspection first:** Confirm the hypothesis with at least two independent evidence sources.
6. **Control the test:** Make only one bounded change and define the rollback command in advance.
7. **Measure service behavior:** Validate latency, throughput, errors, data consistency, authentication, and client experience.
8. **Persist correctly:** Apply successful changes through the supported configuration source rather than an ad hoc runtime command.
9. **Close the incident:** Document root cause, contributing conditions, corrective action, monitoring, and prevention.

## 9. Production cautions

- List untrusted archives before extraction and extract into an isolated directory.
- Avoid restoring ownership as root from untrusted archives.
- Preserve ACLs, xattrs, SELinux labels, hard links, and sparse files when required.
- Do not archive live application data without application-consistent snapshot or quiescing.
- Replace all example users, paths, devices, addresses, ports, repositories, and services only after validation.
- Keep console or out-of-band access for firewall, bootloader, storage, authentication, and network changes.
- Back up data and configuration before destructive, recursive, or boot-critical commands.
