# 119. getfattr

> **Level:** Linux Corporate/L3 administration and troubleshooting.

## 1. What it is

`getfattr` displays extended attributes (xattrs) attached to files and directories. Xattrs store metadata such as SELinux labels, file capabilities, user-defined attributes, and filesystem-specific information.

## 2. Why it matters in production

- Provides a repeatable method to inspect, validate, or control an important Linux subsystem.
- Produces evidence that can be attached to incident, change, problem, audit, and capacity records.
- Helps distinguish configuration, permission, kernel, service, network, storage, security, and application failures.
- Supports before-and-after validation rather than unmeasured configuration changes.

## 4. Core concepts

- Namespaces include `user.`, `security.`, `system.`, and `trusted.`.
- Access to security and trusted attributes normally requires privilege.
- The `security.selinux` and `security.capability` attributes are operationally important.
- Not every filesystem or network protocol preserves every xattr namespace.
- Backups and copies must explicitly preserve xattrs when required.
- Large recursive xattr scans can generate significant metadata I/O.

## 5. Important commands

| Command | Purpose | Operational risk |
|---|---|---|
| `getfattr -d /path/file` | Display user-visible extended attributes. | Read-only |
| `getfattr -m - -d /path/file` | Display attributes from all namespaces when permitted. | Read-only |
| `getfattr -n user.comment /path/file` | Read one named attribute. | Read-only |
| `getfattr -n security.selinux /path/file` | Read the SELinux label xattr. | Read-only |
| `getfattr -n security.capability -e hex /path/file` | Read file capabilities in hexadecimal form. | Read-only |
| `getfattr -R -d -m 'user\..*' /data/project` | Recursively display user namespace attributes. | Read-only |
| `getfattr --absolute-names -R -d /data/project > /root/project.xattrs` | Export xattrs using absolute paths. | Read-only |
| `setfattr -n user.comment -v 'lab file' /path/file` | Set a user attribute. | Metadata change |
| `setfattr -x user.comment /path/file` | Remove a user attribute. | Metadata change |
| `cp -a --preserve=xattr /source /destination` | Copy while preserving xattrs. | Read-only |
| `rsync -aX /source/ /destination/` | Synchronize and preserve xattrs. | Read-only |

## 7. How to interpret the output

- Values can be displayed as quoted text, hexadecimal, or base64 depending on content and options.
- No output can mean no matching attributes, insufficient privilege, or unsupported xattrs.
- A `# file:` header identifies the object whose attributes follow.
- Unexpected SELinux or capability attributes should be validated with specialized tools.
- File replacement can remove attributes even when the pathname remains the same.

## 8. L3 troubleshooting workflow

1. **Define impact:** Identify the affected service, users, start time, scope, and business symptom.
2. **Preserve evidence:** Capture relevant logs, configuration, counters, timestamps, versions, and current state.
3. **Confirm ownership:** Determine whether systemd, NetworkManager, authselect, firewalld, policy, automation, or another manager owns the configuration.
4. **Use read-only checks first:** Avoid changing state before the failure mode is understood.
5. **Correlate adjacent layers:** Check process, kernel, filesystem, network, DNS, time, identity, audit, and SELinux evidence as appropriate.
6. **Form one hypothesis:** State what evidence supports it and what observation would disprove it.
7. **Make one controlled change:** Use a maintenance window, backup, console path, and rollback command.
8. **Validate service metrics:** Confirm application latency, error rate, authentication, data integrity, and logs—not only command success.
9. **Restore or persist:** Roll back failed experiments and make successful changes through approved configuration management.
10. **Document RCA:** Record root cause, contributing factors, corrective action, prevention, and monitoring.

## 9. Production cautions

- Do not change `security.selinux` or `security.capability` directly with generic tools in routine administration.
- Protect exported xattr inventories because they can reveal security policy.
- Verify backup software preserves required attributes.
- Use scoped recursion on large filesystems.
- Never copy example users, paths, ports, addresses, or devices into production without validation.
- Commands that change credentials, access, labels, firewall rules, packages, audit rules, or services require change control.
- Keep an independent administrative path for SSH, PAM, firewall, DNS, and authentication work.

## 10. Quick practice lab

3. Copy the file with and without xattr preservation.
