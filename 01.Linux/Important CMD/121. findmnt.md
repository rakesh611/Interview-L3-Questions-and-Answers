# 121. findmnt

> **Level:** Linux Corporate/L3 administration and troubleshooting.

## 1. What it is

`findmnt` searches live mount tables and `/etc/fstab`, resolves the mount containing a pathname, and displays mount hierarchy, propagation, source, filesystem type, and effective options.

## 2. Why it matters in production

- Provides a repeatable method to inspect, validate, or control an important Linux subsystem.
- Produces evidence that can be attached to incident, change, problem, audit, and capacity records.
- Helps distinguish configuration, permission, kernel, service, network, storage, security, and application failures.
- Supports before-and-after validation rather than unmeasured configuration changes.

## 4. Core concepts

- The live kernel mount table is different from persistent `/etc/fstab`.
- Mount namespaces can give a service or container a different view from the administrator shell.
- Bind mounts can expose the same filesystem at multiple paths.
- Propagation flags affect whether nested mount events cross namespace boundaries.
- The source shown can be a UUID, mapper device, network export, overlay, or pseudo filesystem.
- Explicit columns or JSON are safer for automation than default output.

## 5. Important commands

| Command | Purpose | Operational risk |
|---|---|---|
| `findmnt` | Display the live mount tree. | Read-only |
| `findmnt -T /var/log/messages` | Find the mount containing a path. | Read-only |
| `findmnt /data` | Display one target. | Read-only |
| `findmnt -S UUID=1111-2222` | Search by source. | Read-only |
| `findmnt -t xfs,ext4,nfs4` | Filter by filesystem type. | Read-only |
| `findmnt -o TARGET,SOURCE,FSTYPE,OPTIONS,VFS-OPTIONS,FS-OPTIONS,PROPAGATION` | Display detailed selected columns. | Read-only |
| `findmnt --fstab` | Display fstab entries. | Read-only |
| `findmnt --verify --verbose` | Validate fstab entries. | Read-only |
| `findmnt --poll --target /data` | Monitor mount-table changes for a target. | Read-only |
| `findmnt -J -o TARGET,SOURCE,FSTYPE,OPTIONS` | Produce JSON output. | Read-only |
| `nsenter -t 1234 -m findmnt` | Inspect the mount namespace of PID 1234. | Read-only |
| `findmnt -R /var/lib/containers` | Show recursive submounts. | Read-only |

## 7. How to interpret the output

- `TARGET` is the mount point visible in the selected namespace.
- `SOURCE` can contain bracketed subvolume or bind-source information.
- `VFS-OPTIONS` are generic mount-layer options; `FS-OPTIONS` are filesystem-specific.
- `shared`, `slave`, `private`, and `unbindable` describe propagation.
- `findmnt -T` is safer than guessing which filesystem owns a deeply nested path.

## 8. L3 troubleshooting workflow

1. **Define impact:** Identify the affected service, users, start time, scope, and business symptom.
2. **Preserve evidence:** Capture relevant logs, configuration, counters, timestamps, versions, and current state.
3. **Confirm ownership:** Determine whether systemd, NetworkManager, authselect, firewalld, policy, automation, or another manager owns the configuration.
4. **Use read-only checks first:** Avoid changing state before the failure mode is understood.
5. **Correlate adjacent layers:** Check process, kernel, filesystem, network, DNS, time, identity, audit, and SELinux evidence as appropriate.
6. **Form one hypothesis:** State what evidence supports it and what observation would disprove it.
7. **Make one controlled change:** Use a maintenance window, backup, console path, and rollback command.
8. **Validate service metrics:** Confirm application latency, error rate, authentication, data integrity, and logs—not only command success.
9. **Restore or persist:** Roll back failed experiments and make successful changes through approved configuration management.
10. **Document RCA:** Record root cause, contributing factors, corrective action, prevention, and monitoring.

## 9. Production cautions

- Run namespace-aware checks for containers and systemd services.
- Validate fstab after every persistent change and before reboot.
- Do not assume one source has only one mount point.
- Protect output that exposes sensitive network exports or paths.
- Never copy example users, paths, ports, addresses, or devices into production without validation.
- Commands that change credentials, access, labels, firewall rules, packages, audit rules, or services require change control.
- Keep an independent administrative path for SSH, PAM, firewall, DNS, and authentication work.

## 10. Quick practice lab

1. Create a bind mount.
2. Compare tree and list output.
3. Resolve a file beneath the bind mount.
4. Inspect propagation.
5. Enter a test mount namespace and compare views.
