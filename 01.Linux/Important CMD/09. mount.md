# mount — Important Linux Commands and Practical Examples

**File:** `01. mount Important Commands.mdd`  
**Level:** Linux Administration / Corporate L2-L3  
**Platforms:** RHEL, CentOS Stream, Rocky Linux, AlmaLinux, Fedora, Ubuntu and Debian  
**Related commands:** `findmnt`, `lsblk`, `blkid`, `df`, `mountpoint`, `umount`, `fsck`, `xfs_repair`

---

# 1. What is `mount`?

The `mount` command attaches a filesystem to the Linux directory tree.

Linux does not normally use separate drive letters such as `C:` or `D:`. A disk,
partition, logical volume, network share or image is attached to a directory called a
**mount point**.

Example:

```text
/dev/sdb1              -> /data
/dev/vgdata/lvbackup   -> /backup
server:/export         -> /mnt/nfs
```

After mounting `/dev/sdb1` on `/data`, files on that filesystem are accessed through:

```bash
/data
```

Basic example:

```bash
sudo mkdir -p /data
sudo mount /dev/sdb1 /data
```

Verify:

```bash
findmnt /data
df -hT /data
```

Unmount:

```bash
sudo umount /data
```

A command-line mount is normally temporary. To mount the filesystem automatically
after reboot, configure `/etc/fstab` or a systemd mount unit.

# 2. Linux mount terminology

## Filesystem

A filesystem controls how files and directories are stored.

Common examples:

```text
xfs
ext4
btrfs
vfat
ntfs
nfs
cifs
tmpfs
iso9660
overlay
```

## Block device

A block device can be a disk, partition, LVM logical volume, RAID device or SAN LUN.

Examples:

```text
/dev/sda
/dev/sda1
/dev/sdb2
/dev/nvme0n1p1
/dev/vgdata/lvdata
/dev/mapper/rhel-root
/dev/md0
```

## Mount point

A mount point is a directory where a filesystem is attached.

Examples:

```text
/
/boot
/home
/data
/backup
/mnt/nfs
```

## Mount option

Mount options control filesystem behavior.

Examples:

```text
rw
ro
noexec
nosuid
nodev
relatime
noatime
nofail
_netdev
```

# 4. Basic syntax

```bash
mount [OPTIONS] DEVICE MOUNT_POINT
```

Example:

```bash
sudo mount /dev/sdb1 /data
```

Specify filesystem type:

```bash
sudo mount -t xfs /dev/sdb1 /data
```

Specify options:

```bash
sudo mount -o ro /dev/sdb1 /data
```

Specify both:

```bash
sudo mount -t xfs -o ro /dev/sdb1 /data
```


# 7. Mount by filesystem type

Mount XFS:

```bash
sudo mount -t xfs /dev/sdb1 /data
```

Mount ext4:

```bash
sudo mount -t ext4 /dev/sdb1 /data
```

Mount FAT:

```bash
sudo mount -t vfat /dev/sdb1 /mnt/usb
```

Mount an NTFS filesystem when support is installed:

```bash
sudo mount -t ntfs3 /dev/sdb1 /mnt/windows
```

Normally `mount` detects the type automatically by reading filesystem metadata.

---

# 8. Mount read-only and read-write

Mount read-only:

```bash
sudo mount -o ro /dev/sdb1 /data
```

Verify:

```bash
findmnt -no OPTIONS /data
```

Read-only mounts are useful for:

- Incident investigation.
- Damaged-filesystem analysis.
- Backup verification.
- Preventing accidental writes.
- Mounting installation media.

Mount read-write:

```bash
sudo mount -o rw /dev/sdb1 /data
```

Most local filesystems mount read-write by default.

---

# 9. Remount an existing filesystem

Change a mounted filesystem to read-only:

```bash
sudo mount -o remount,ro /data
```

Change it back to read-write:

```bash
sudo mount -o remount,rw /data
```

In rescue mode, remount root read-write:

```bash
sudo mount -o remount,rw /
```

Production caution:

```text
Do not remount a filesystem read-only while applications are actively writing to it.
```

# 10. Mount by UUID

Display UUIDs:

```bash
lsblk -f
sudo blkid
```

Example:

```text
/dev/sdb1: UUID="68994380-5d43-4a4a-a403-30fbc776183a" TYPE="xfs"
```

Mount by UUID:

```bash
sudo mount UUID=68994380-5d43-4a4a-a403-30fbc776183a /data
```

UUIDs are preferred in `/etc/fstab` because names such as `/dev/sdb1` can change after
hardware or boot-order changes.

# 14. Mount all `/etc/fstab` filesystems

```bash
sudo mount -a
```

This mounts valid `/etc/fstab` entries except entries using options such as `noauto`.

Verbose validation:

```bash
sudo mount -av
```

Always run this after changing `/etc/fstab`:

```bash
sudo cp -a /etc/fstab "/etc/fstab.backup.$(date +%F-%H%M%S)"
sudo vi /etc/fstab
sudo systemctl daemon-reload
sudo mount -av
```

Check status:

```bash
echo $?
systemctl --failed --type=mount
```

# 15. Mount one `/etc/fstab` entry

Example entry:

```text
UUID=68994380-5d43-4a4a-a403-30fbc776183a /data xfs defaults 0 0
```

Mount it using only the mount point:

```bash
sudo mount /data
```

`mount` reads the device, type and options from `/etc/fstab`.

# 16. Important mount options

## `defaults`

Typical default behavior:

```text
rw,suid,dev,exec,auto,nouser,async
```

Example:

```bash
sudo mount -o defaults /dev/sdb1 /data
```

## `ro`

Read-only:

```bash
sudo mount -o ro /dev/sdb1 /data
```

## `rw`

Read-write:

```bash
sudo mount -o rw /dev/sdb1 /data
```

## `noexec`

Prevent direct execution of programs from the filesystem:

```bash
sudo mount -o noexec /dev/sdb1 /data
```

Important:

```text
noexec is a hardening control, not a complete security boundary.
```

A script may still be read by an interpreter:

```bash
bash /data/script.sh
```

## `nosuid`

Ignore set-user-ID and set-group-ID bits:

```bash
sudo mount -o nosuid /dev/sdb1 /data
```

## `nodev`

Do not interpret device files on this filesystem:

```bash
sudo mount -o nodev /dev/sdb1 /data
```

## Combined hardening

```bash
sudo mount -o nodev,nosuid,noexec /dev/sdb1 /data
```

Persistent example:

```text
UUID=<uuid> /data xfs defaults,nodev,nosuid,noexec 0 0
```

Use these options only after checking application requirements.

## `sync`

Perform I/O synchronously:

```bash
sudo mount -o sync /dev/sdb1 /data
```

This may reduce performance significantly.

## `async`

Allow asynchronous I/O:

```bash
sudo mount -o async /dev/sdb1 /data
```

## `noatime`

Do not update file access times:

```bash
sudo mount -o noatime /dev/sdb1 /data
```

## `relatime`

Update access time only under defined conditions:

```bash
sudo mount -o relatime /dev/sdb1 /data
```

This is common on modern Linux systems.

## `discard`

Enable online discard/TRIM:

```bash
sudo mount -o discard /dev/sdb1 /data
```

Many enterprise systems prefer periodic trimming:

```bash
sudo systemctl enable --now fstrim.timer
sudo fstrim -av
```

## `nofail`

Allow boot to continue when a non-critical mount fails:

```text
UUID=<uuid> /backup xfs defaults,nofail 0 0
```

Risk:

```text
An application may write into the empty mount-point directory on the root filesystem.
```

## `noauto`

Do not mount automatically during boot or with `mount -a`:

```text
UUID=<uuid> /archive xfs defaults,noauto 0 0
```

Manual mount:

```bash
sudo mount /archive
```

## `_netdev`

Marks a filesystem as network dependent:

```text
server:/export /mnt/nfs nfs defaults,_netdev 0 0
```

## `uid`, `gid` and `umask`

Useful for filesystems without normal Linux ownership metadata:

```bash
sudo mount -t vfat -o uid=1000,gid=1000,umask=022 /dev/sdb1 /mnt/usb
```

# 17. `/etc/fstab` format

Display:

```bash
cat /etc/fstab
```

Example:

```text
UUID=1111-2222 /boot/efi vfat umask=0077,shortname=winnt 0 2
UUID=68994380-5d43-4a4a-a403-30fbc776183a /data xfs defaults 0 0
/dev/mapper/rhel-root / xfs defaults 0 0
```

The six fields are:

```text
1. Device or filesystem source
2. Mount point
3. Filesystem type
4. Mount options
5. dump field
6. filesystem-check order
```

XFS example:

```text
UUID=<uuid> /data xfs defaults 0 0
```

Ext4 example:

```text
UUID=<uuid> /data ext4 defaults 0 2
```

# 18. Safe persistent-mount procedure

## Step 1: Identify the filesystem

```bash
lsblk -f
sudo blkid
```

## Step 2: Create mount point

```bash
sudo mkdir -p /data
```

## Step 3: Check whether it contains files

```bash
sudo find /data -mindepth 1 -maxdepth 1 -ls
```

## Step 4: Test temporary mount

```bash
sudo mount /dev/sdb1 /data
findmnt /data
df -hT /data
```

## Step 5: Test read and write

```bash
sudo touch /data/.mount_test
sudo rm -f /data/.mount_test
```

## Step 6: Unmount

```bash
sudo umount /data
```

## Step 7: Back up fstab

```bash
sudo cp -a /etc/fstab "/etc/fstab.backup.$(date +%F-%H%M%S)"
```

## Step 8: Add UUID entry

```text
UUID=68994380-5d43-4a4a-a403-30fbc776183a /data xfs defaults 0 0
```

## Step 9: Validate

```bash
sudo systemctl daemon-reload
sudo mount -av
```

## Step 10: Verify

```bash
findmnt /data
df -hT /data
systemctl status data.mount
```

# 19. Mount XFS

Create an XFS filesystem only on a new or disposable device:

```bash
sudo mkfs.xfs /dev/sdb1
```

Mount:

```bash
sudo mkdir -p /data
sudo mount -t xfs /dev/sdb1 /data
```

Verify:

```bash
findmnt /data
sudo xfs_info /data
```

Grow after extending the underlying device:

```bash
sudo xfs_growfs /data
```

Important:

- XFS normally cannot be shrunk.
- XFS repair uses `xfs_repair`.
- Do not run `mkfs.xfs` on a filesystem containing required data.

# 24. Bind mount

A bind mount exposes an existing directory at another path.

```bash
sudo mkdir -p /data
sudo mount --bind /app/data /data
```

Verify:

```bash
findmnt /data
```

Persistent `/etc/fstab` entry:

```text
/app/data /data none bind 0 0
```

Read-only bind mount:

```bash
sudo mount --bind /app/data /data
sudo mount -o remount,bind,ro /data
```

---

# 25. Recursive bind mounts and propagation

Recursive bind mount:

```bash
sudo mount --rbind /source /target
```

Make it recursively private:

```bash
sudo mount --make-rprivate /target
```

Check propagation:

```bash
findmnt -o TARGET,PROPAGATION
```

Other propagation controls:

```bash
sudo mount --make-private /target
sudo mount --make-shared /target
sudo mount --make-slave /target
```

These options are important in chroot, container and Kubernetes environments.

---

# 26. Mount tmpfs

A `tmpfs` filesystem stores data primarily in memory and may use swap.

```bash
sudo mkdir -p /mnt/ram
sudo mount -t tmpfs -o size=1G tmpfs /mnt/ram
```

Verify:

```bash
findmnt /mnt/ram
df -hT /mnt/ram
```

Persistent example:

```text
tmpfs /mnt/ram tmpfs size=1G,mode=0750 0 0
```

Use cases:

- Temporary application files.
- Caches.
- Build workspaces.
- Sensitive temporary data.

# 27. Mount an NFS share

Install client package on RHEL:

```bash
sudo dnf install nfs-utils
```

List exports:

```bash
showmount -e nfsserver.example.com
```

Mount:

```bash
sudo mkdir -p /mnt/nfs
sudo mount -t nfs nfsserver.example.com:/export/data /mnt/nfs
```

Specify NFS version:

```bash
sudo mount -t nfs -o vers=4.2 nfsserver.example.com:/export/data /mnt/nfs
```

Verify:

```bash
findmnt /mnt/nfs
nfsstat -m
```

Persistent entry:

```text
nfsserver.example.com:/export/data /mnt/nfs nfs defaults,_netdev 0 0
```

Important NFS options:

```text
vers=4.2
hard
soft
timeo=
retrans=
rsize=
wsize=
_netdev
```

For critical data, `hard` mounts are commonly preferred. `soft` can return errors to
applications and must be used only after understanding data-integrity risk.

# 28. Mount CIFS or SMB

Install tools:

```bash
sudo dnf install cifs-utils
```

Create mount point:

```bash
sudo mkdir -p /mnt/share
```

Mount interactively:

```bash
sudo mount -t cifs //fileserver/share /mnt/share -o username=myuser
```

Create a credentials file:

```bash
sudo vi /root/.smbcredentials
```

Content:

```text
username=myuser
password=MySecretPassword
domain=EXAMPLE
```

Secure it:

```bash
sudo chmod 600 /root/.smbcredentials
```

Mount:

```bash
sudo mount -t cifs //fileserver/share /mnt/share \
  -o credentials=/root/.smbcredentials,vers=3.1.1
```

Persistent entry:

```text
//fileserver/share /mnt/share cifs credentials=/root/.smbcredentials,vers=3.1.1,_netdev 0 0
```

# 30. Chroot recovery mount procedure

Assume root filesystem:

```text
/dev/mapper/rhel-root
```

Mount root:

```bash
sudo mkdir -p /mnt/sysroot
sudo mount /dev/mapper/rhel-root /mnt/sysroot
```

Mount boot and EFI as applicable:

```bash
sudo mount /dev/sda2 /mnt/sysroot/boot
sudo mount /dev/sda1 /mnt/sysroot/boot/efi
```

Bind runtime filesystems:

```bash
sudo mount --rbind /dev /mnt/sysroot/dev
sudo mount --make-rslave /mnt/sysroot/dev
sudo mount -t proc proc /mnt/sysroot/proc
sudo mount -t sysfs sysfs /mnt/sysroot/sys
sudo mount --rbind /run /mnt/sysroot/run
sudo mount --make-rslave /mnt/sysroot/run
```

Enter chroot:

```bash
sudo chroot /mnt/sysroot
```

# 34. Troubleshoot `target is busy`

Error:

```text
umount: /data: target is busy
```

Find processes using it:

```bash
sudo lsof +f -- /data
sudo fuser -vm /data
```

Check nested mounts:

```bash
findmnt -R /data
```

Common causes:

- A process has an open file.
- A shell is inside the directory.
- A process uses it as its working directory.
- A nested filesystem is mounted below it.
- Swap uses a file inside it.

Terminate users only after review:

```bash
sudo fuser -km /data
```

Do not use `fuser -k` blindly on production servers.

---

# 35. Lazy and forced unmount

Lazy unmount:

```bash
sudo umount -l /data
```

It detaches the mount immediately and cleans references after processes release them.

Forced unmount:

```bash
sudo umount -f /mnt/nfs
```

Forced unmount is mainly used for unreachable network filesystems and may cause I/O
errors, application failure or data loss.

# 36. Common mount errors

## Mount point does not exist

```text
mount: /data: mount point does not exist
```

Fix:

```bash
sudo mkdir -p /data
```

## Wrong filesystem type or bad superblock

```text
mount: wrong fs type, bad option, bad superblock
```

Check:

```bash
lsblk -f
sudo blkid /dev/sdb1
sudo file -s /dev/sdb1
dmesg -T | tail -50
```

Possible causes:

- Wrong filesystem type.
- Damaged filesystem.
- Missing helper package.
- Device contains LVM, RAID or encryption instead of a filesystem.
- Invalid mount option.

## Special device does not exist

```text
mount: special device /dev/sdb1 does not exist
```

Check:

```bash
lsblk
ls -l /dev/sd*
dmesg -T | tail
```

## Permission denied

Check:

```bash
id
ls -ld /data
findmnt -no OPTIONS /data
getenforce
```

## Unknown filesystem type

Check supported filesystems:

```bash
cat /proc/filesystems
```

Install helpers as required:

```bash
sudo dnf install nfs-utils
sudo dnf install cifs-utils
```

## Read-only filesystem

Check:

```bash
findmnt -no TARGET,SOURCE,FSTYPE,OPTIONS /data
dmesg -T | tail -100
```

The kernel may remount a damaged filesystem read-only. Do not force read-write until
the cause is understood.

# 39. Custom systemd mount unit

Create:

```bash
sudo vi /etc/systemd/system/data.mount
```

Example:

```ini
[Unit]
Description=Application Data Filesystem
Before=local-fs.target

[Mount]
What=/dev/disk/by-uuid/68994380-5d43-4a4a-a403-30fbc776183a
Where=/data
Type=xfs
Options=defaults,nodev,nosuid

[Install]
WantedBy=local-fs.target
```

Create mount point and activate:

```bash
sudo mkdir -p /data
sudo systemctl daemon-reload
sudo systemctl enable --now data.mount
```

Verify:

```bash
systemctl status data.mount
findmnt /data
```

The unit filename must exactly match the escaped mount point.

# 40. systemd automount

Create `data.automount`:

```ini
[Unit]
Description=Automount Application Data

[Automount]
Where=/data
TimeoutIdleSec=300

[Install]
WantedBy=multi-user.target
```

Enable:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now data.automount
```

Accessing the directory triggers the mount:

```bash
ls /data
```

Alternatively, use `/etc/fstab`:

```text
UUID=<uuid> /data xfs defaults,x-systemd.automount 0 0
```

# 43. Mount encrypted storage

```bash

```

Mount the mapped device:


Verify:

```bash
findmnt /secure
sudo cryptsetup status secure_data
```

```bash

```

Persistent encrypted storage normally uses `/etc/crypttab` and `/etc/fstab`.

# 44. Mount RAID and multipath storage


# 45. Mounting over a non-empty directory

Suppose `/data` contains files:

```bash
ls -la /data
```

After mounting another filesystem on `/data`, those files become hidden:

```bash
sudo mount /dev/sdb1 /data
```

They are not deleted. They become visible again after unmounting:

```bash
sudo umount /data
ls -la /data
```

Always inspect the mount point before mounting:

```bash
sudo find /data -mindepth 1 -maxdepth 1 -ls
```

# 46. Accidental writes under a failed mount point

Scenario:

```text
/data should be a separate filesystem.
The mount fails during boot.
The application writes into /data on the root filesystem.
```

Check:

```bash
mountpoint -q /data || echo 'WARNING: /data is not mounted'
findmnt -T /data
df -h /
sudo du -sh /data
```

A systemd service can require the mount:

```bash
sudo systemctl edit myapp.service
```

Add:

```ini
[Unit]
RequiresMountsFor=/data
After=data.mount
```

Reload:

```bash
sudo systemctl daemon-reload
sudo systemctl restart myapp.service
```

# 47. Root filesystem full because data is hidden below a mount

Bind mount root elsewhere:

```bash
sudo mkdir -p /mnt/root-view
sudo mount --bind / /mnt/root-view
```

Inspect the underlying directory even while `/data` is mounted:

```bash
sudo du -sh /mnt/root-view/data
```

Cleanup:

```bash
sudo umount /mnt/root-view
```

This is useful when files were written into a mount-point directory before the real
filesystem mounted.

# 50. Safe mount script

```bash
#!/usr/bin/env bash
set -euo pipefail

DEVICE="/dev/sdb1"
MOUNT_POINT="/data"

if [[ ! -b "$DEVICE" ]]; then
    echo "ERROR: $DEVICE is not a block device." >&2
    exit 1
fi

sudo mkdir -p "$MOUNT_POINT"

if mountpoint -q "$MOUNT_POINT"; then
    echo "$MOUNT_POINT is already mounted."
    findmnt "$MOUNT_POINT"
    exit 0
fi

sudo mount "$DEVICE" "$MOUNT_POINT"

if mountpoint -q "$MOUNT_POINT"; then
    echo "Mount successful."
    findmnt "$MOUNT_POINT"
else
    echo "ERROR: Mount verification failed." >&2
    exit 1
fi
```

# 52. Production checklist

Before mounting:

```text
1. Confirm the correct device.
2. Confirm filesystem type.
3. Confirm the device is not already mounted.
4. Confirm the mount point exists.
5. Check whether the mount point contains files.
6. Confirm ownership and permissions.
7. Confirm SELinux requirements.
8. Test the mount manually.
9. Verify read and write behavior.
10. Record the UUID or stable device name.
```

Before editing `/etc/fstab`:

```text
1. Back up /etc/fstab.
2. Prefer UUID, label, LVM path or multipath WWID.
3. Use the correct filesystem type.
4. Add _netdev for network-dependent storage.
5. Use nofail only for non-critical filesystems.
6. Validate with mount -av.
7. Verify with findmnt.
8. Check systemctl --failed.
9. Ensure applications depend on required mounts.
10. Reboot only during an approved change window.
```

# 54. Final summary

The `mount` command attaches a local, virtual or network filesystem to the Linux
directory tree.

The most important commands are:

```bash
sudo mount /dev/sdb1 /data
sudo mount -t xfs /dev/sdb1 /data
sudo mount -o ro /dev/sdb1 /data
sudo mount -o remount,rw /data
sudo mount UUID=<uuid> /data
sudo mount --bind /source /target
sudo mount -a
sudo mount -av
findmnt /data
mountpoint /data
sudo umount /data
```

For production systems:

- Prefer UUIDs or stable device-mapper names.
- Back up `/etc/fstab` before changing it.
- Test changes with `mount -av` before reboot.
- Verify the source and options with `findmnt`.
- Do not mount over a directory containing important files without a migration plan.
- Prevent applications from starting if their required filesystems are unavailable.
- Investigate logs before using lazy or forced unmount.
- Never run `mkfs` simply because a device does not mount.
