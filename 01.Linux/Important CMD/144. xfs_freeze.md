# 144. xfs_freeze

> **Scope:** Corporate/L3 Linux administration, incident troubleshooting, safe change execution, and interview preparation.

## 1. What it is

`xfs_freeze` freezes and unfreezes a mounted XFS filesystem. Modern generic workflows can use `fsfreeze`, but `xfs_freeze` remains an XFS-specific administration tool.

## 2. Production importance

- Provides a repeatable method for diagnosing or controlling the relevant Linux subsystem.
- Produces evidence suitable for incident timelines, change records, problem management, and audit review.
- Encourages before-and-after measurement instead of unverified tuning or repair.
- Separates command success from actual application availability, security, and data integrity.

## 3. Package or kernel interface

- **Primary package/interface:** xfsprogs
- Check availability and installed version before relying on an option:

```bash
command -v xfs_freeze 2>/dev/null || true
rpm -q PACKAGE_NAME 2>/dev/null || true
COMMAND --version 2>/dev/null || COMMAND --help
```

## 4. Core concepts

- The filesystem must be mounted and must be XFS.
- Writers can block while frozen, creating immediate service latency.
- A freeze is useful only when coordinated with the external snapshot operation.
- XFS log and metadata are brought to a consistent frozen state for crash-consistent snapshots.
- Application-level buffers and distributed transactions require separate quiescing.
- The unfreeze command must be available through an unaffected administrative path.

## 5. Important commands

| Command | Purpose | Risk |
|---|---|---|
| `xfs_info /data` | Confirm that the target is an XFS filesystem. | Read-only |
| `findmnt /data -o TARGET,SOURCE,FSTYPE,OPTIONS` | Confirm the mounted source. | Read-only |
| `sudo xfs_freeze -f /data` | Freeze the XFS filesystem. | Immediate application-write suspension |
| `sudo xfs_freeze -u /data` | Unfreeze the XFS filesystem. | Recovery operation |
| `xfs_freeze -V` | Display the tool version. | Read-only |
| `sudo lvcreate -s -L 10G -n data_snap /dev/vgdata/lvdata` | Create an LVM snapshot during the freeze. | Storage snapshot creation |
| `sudo lvs -o lv_name,lv_size,origin,data_percent,devices` | Verify snapshot state. | Read-only |
| `journalctl -k --since '-10 min' \| grep -i xfs` | Review XFS kernel messages. | Read-only |
| `ps -eo pid,stat,wchan:32,cmd \| awk '$2 ~ /^D/'` | Find blocked tasks. | Read-only |
| `sudo fsfreeze -u /data` | Generic unfreeze alternative supported by the filesystem. | Recovery operation |

## 7. Output interpretation

- Successful freeze/unfreeze is normally silent.
- Blocked writers are expected during the freeze but should recover immediately afterward.
- An LVM snapshot `Data%` must be monitored if retained.
- A snapshot is only crash-consistent unless the application was quiesced.
- XFS error messages during freeze require storage and filesystem investigation.

## 8. Corporate/L3 troubleshooting workflow

1. **Confirm impact:** Record affected applications, users, start time, error rate, latency, and business severity.
2. **Identify scope:** Determine whether the issue is host-wide, process-specific, filesystem-specific, network-path-specific, or limited to one namespace.
3. **Preserve evidence:** Save logs, configuration, counters, command output, package versions, and timestamps before changing state.
4. **Establish ownership:** Identify whether systemd, NetworkManager, firewalld, TuneD, udev, a backup scheduler, configuration management, or the application owns the setting.
5. **Use read-only inspection first:** Confirm the hypothesis with at least two independent evidence sources.
6. **Control the test:** Make only one bounded change and define the rollback command in advance.
7. **Measure service behavior:** Validate latency, throughput, errors, data consistency, authentication, and client experience.
8. **Persist correctly:** Apply successful changes through the supported configuration source rather than an ad hoc runtime command.
9. **Close the incident:** Document root cause, contributing conditions, corrective action, monitoring, and prevention.

## 9. Production cautions

- Do not freeze the root filesystem during an untested remote procedure.
- Pre-stage the snapshot and unfreeze commands.
- Do not leave the filesystem frozen while copying large backup data.
- Use database-native backup or quiescing integration where required.
- Replace all example users, paths, devices, addresses, ports, repositories, and services only after validation.
- Keep console or out-of-band access for firewall, bootloader, storage, authentication, and network changes.
- Back up data and configuration before destructive, recursive, or boot-critical commands.

## 10. Practice lab

1. Create a lab XFS LV.
2. Generate writes.
3. Freeze and snapshot it.
4. Unfreeze within seconds.
5. Mount the snapshot read-only and validate consistency.
