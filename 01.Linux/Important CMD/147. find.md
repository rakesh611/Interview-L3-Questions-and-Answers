# 147. find

> **Scope:** Corporate/L3 Linux administration, incident troubleshooting, safe change execution, and interview preparation.

## 1. What it is

`find` recursively searches directory trees using file metadata and can print, format, execute commands, delete objects, or feed NUL-delimited results to other tools.

## 2. Production importance

- Provides a repeatable method for diagnosing or controlling the relevant Linux subsystem.
- Produces evidence suitable for incident timelines, change records, problem management, and audit review.
- Encourages before-and-after measurement instead of unverified tuning or repair.
- Separates command success from actual application availability, security, and data integrity.

## 3. Package or kernel interface

- **Primary package/interface:** findutils
- Check availability and installed version before relying on an option:

```bash
command -v find 2>/dev/null || true
rpm -q PACKAGE_NAME 2>/dev/null || true
COMMAND --version 2>/dev/null || COMMAND --help
```

## 4. Core concepts

- Expressions are evaluated left to right with operator precedence.
- Tests such as `-mtime` use rounded 24-hour periods; `-newermt` uses readable timestamps.
- `-xdev` prevents crossing filesystem boundaries.
- `-print0` and NUL-aware consumers safely handle unusual filenames.
- `-delete` is destructive and implies depth-first behavior in GNU find.
- `-exec ... {} +` batches arguments and is usually more efficient than one process per file.

## 5. Important commands

| Command | Purpose | Risk |
|---|---|---|
| `find /var/log -type f -name '*.log' -print` | Find log files by name. | Read-only |
| `find /data -xdev -type f -size +1G -printf '%s %p\n' \| sort -n` | Find large files without crossing filesystems. | Read-only |
| `find /data -type f -newermt '2026-07-28 10:00:00' ! -newermt '2026-07-28 11:00:00' -print` | Find files changed in a time window. | Read-only |
| `find /home -xdev -type f -user olduser -print` | Find files by owner. | Read-only |
| `find /srv -type f -perm /002 -print` | Find world-writable files. | Read-only |
| `find /tmp -xdev -type f -mtime +30 -print` | Preview files older than 30 rounded days. | Read-only |
| `find /tmp -xdev -type f -mtime +30 -delete` | Delete matched old files. | Destructive recursive deletion |
| `find /data -type f -print0 \| xargs -0 sha256sum` | Hash files safely. | Read-only |
| `find /data -type f -exec chmod 0640 {} +` | Batch a command over matched files. | Bulk permission change |
| `find /data -samefile /data/file -print` | Find hard links to a file. | Read-only |
| `find /data -xdev -inum 12345 -print` | Find a pathname by inode. | Read-only |
| `find /var -type f -links +1 -printf '%n %i %p\n'` | Find multiply linked files. | Read-only |
| `find / -fstype nfs -prune -o -type f -name core -print` | Prune NFS trees while searching. | Read-only |

## 7. Output interpretation

- `-mtime +30` does not mean an exact timestamp older than 30×24 hours in all intuitive senses; use `-newermt` for precise windows.
- Permission errors cause incomplete results unless privilege is sufficient.
- Results can change during traversal.
- A pathname beginning with `-` is safe when produced through `-print0` and consumed correctly.
- An empty result can mean no match, wrong starting path, pruning, permissions, or expression logic.

## 8. Corporate/L3 troubleshooting workflow

1. **Confirm impact:** Record affected applications, users, start time, error rate, latency, and business severity.
2. **Identify scope:** Determine whether the issue is host-wide, process-specific, filesystem-specific, network-path-specific, or limited to one namespace.
3. **Preserve evidence:** Save logs, configuration, counters, command output, package versions, and timestamps before changing state.
4. **Establish ownership:** Identify whether systemd, NetworkManager, firewalld, TuneD, udev, a backup scheduler, configuration management, or the application owns the setting.
5. **Use read-only inspection first:** Confirm the hypothesis with at least two independent evidence sources.
6. **Control the test:** Make only one bounded change and define the rollback command in advance.
7. **Measure service behavior:** Validate latency, throughput, errors, data consistency, authentication, and client experience.
8. **Persist correctly:** Apply successful changes through the supported configuration source rather than an ad hoc runtime command.
9. **Close the incident:** Document root cause, contributing conditions, corrective action, monitoring, and prevention.

## 9. Production cautions

- Replace `-delete` with `-print` during validation.
- Use `-xdev` for cleanup jobs unless crossing mounts is explicitly intended.
- Quote wildcard patterns so the shell does not expand them first.
- Avoid unsafe `for file in $(find ...)` constructions.
- Replace all example users, paths, devices, addresses, ports, repositories, and services only after validation.
- Keep console or out-of-band access for firewall, bootloader, storage, authentication, and network changes.
- Back up data and configuration before destructive, recursive, or boot-critical commands.
