# 115. stat

> **Level:** Linux Corporate/L3 administration and troubleshooting.

## 1. What it is

`stat` reports detailed metadata about files and filesystems. This guide emphasizes forensic and troubleshooting use: timestamps, inode identity, allocation, permissions, ownership, link count, device IDs, and filesystem capacity.

## 2. Why it matters in production

- Provides a repeatable method to inspect, validate, or control an important Linux subsystem.
- Produces evidence that can be attached to incident, change, problem, audit, and capacity records.
- Helps distinguish configuration, permission, kernel, service, network, storage, security, and application failures.
- Supports before-and-after validation rather than unmeasured configuration changes.

## 3. Package and availability

- **Primary package/interface:** coreutils
- Check command availability:

```

```

## 4. Core concepts

- Modification time (`mtime`) tracks file-content change.
- Change time (`ctime`) tracks inode metadata change and is not creation time.
- Access time (`atime`) behavior depends on mount options such as `relatime` or `noatime`.
- Birth time may be unavailable depending on filesystem and kernel support.
- File size and allocated blocks differ for sparse, compressed, or reflinked files.
- Inode number is unique only within one filesystem.

| Command | Purpose | Operational risk |
|---|---|---|
| `stat /etc/passwd` | Display standard file metadata. | Read-only |

| `stat -c 'device=%D major_minor=%t:%T inode=%i' /path/file` | Display device and inode identity. | Read-only |
| `stat -f /data` | Display filesystem metadata. | Read-only |
| `stat -f -c 'type=%T block=%s total=%b free=%f avail=%a files=%c ffree=%d' /data` | Display selected filesystem fields. | Read-only |
| `find /data -xdev -inum 12345 -print` | Locate names linked to an inode. | Read-only |
| `debugfs -R 'stat <12345>' /dev/vgdata/lvext4` | Inspect an ext inode offline or read-only in specialist analysis. | Read-only |

## 7. How to interpret the output

- `Size` is logical bytes, while `Blocks × 512` commonly approximates allocated bytes.
- `Links` greater than one indicates hard links.
- A changed `ctime` without changed `mtime` can indicate permission, owner, ACL, xattr, or link-count modification.
- Rounded shell tools can hide differences that exact `stat` format fields expose.
- Filesystem `free` and `available` differ because reserved capacity may not be available to normal users.

## 8. L3 troubleshooting workflow

1. **Define impact:** Identify the affected service, users, start time, scope, and business symptom.
2. **Preserve evidence:** Capture relevant logs, configuration, counters, timestamps, versions, and current state.
3. **Confirm ownership:** Determine whether systemd, NetworkManager, authselect, firewalld, policy, automation, or another manager owns the configuration.
4. **Use read-only checks first:** Avoid changing state before the failure mode is understood.
5. **Correlate adjacent layers:** Check process, kernel, filesystem, network, DNS, time, identity, audit, and SELinux evidence as appropriate.
6. **Form one hypothesis:** State what evidence supports it and what observation would disprove it.
7. **Make one controlled change:** Use a maintenance window, backup, console path, and rollback command.
8. **Validate service metrics:** Confirm application latency, error rate, authentication, data integrity, and logs—not only command success.
9. **Restore or persist:** Roll back failed experiments and make successful changes through approved configuration management.
10. **Document RCA:** Record root cause, contributing factors, corrective action, prevention, and monitoring.

## 9. Production cautions

- Timestamps can be changed intentionally and are not complete forensic proof.
- Reading a file may update atime depending on mount policy.
- Do not parse locale-dependent default output in scripts.
- Metadata can change after inspection; avoid time-of-check/time-of-use assumptions.
- Never copy example users, paths, ports, addresses, or devices into production without validation.
- Commands that change credentials, access, labels, firewall rules, packages, audit rules, or services require change control.
- Keep an independent administrative path for SSH, PAM, firewall, DNS, and authentication work.

## 10. Quick practice lab

1. Create a normal and sparse file.
2. Compare logical size and allocated blocks.
3. Change mode, content, and ownership separately.
4. Observe timestamp differences.
5. Create a hard link and inspect link count.
