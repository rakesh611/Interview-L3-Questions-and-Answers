# 128. lsof

> **Scope:** Corporate/L3 Linux administration, incident troubleshooting, safe change execution, and interview preparation.

## 1. What it is

`lsof` lists open files and the processes that hold them. Since Linux represents regular files, directories, sockets, pipes, devices, and many kernel objects as file descriptors, it is a powerful cross-subsystem troubleshooting tool.

## 2. Production importance

- Provides a repeatable method for diagnosing or controlling the relevant Linux subsystem.
- Produces evidence suitable for incident timelines, change records, problem management, and audit review.
- Encourages before-and-after measurement instead of unverified tuning or repair.
- Separates command success from actual application availability, security, and data integrity.

## 3. Package or kernel interface

- **Primary package/interface:** lsof
- Check availability and installed version before relying on an option:

```bash
command -v lsof 2>/dev/null || true
rpm -q PACKAGE_NAME 2>/dev/null || true
COMMAND --version 2>/dev/null || COMMAND --help
```

## 4. Core concepts

- An open file remains allocated after deletion until the final file descriptor is closed.
- Root privilege is often required for a complete system-wide view.
- Network selection options can filter by protocol, address, state, and port.
- A process current directory, root directory, mapped library, or executable can make a filesystem busy.
- Some kernel accesses can block or delay `lsof`; scoped queries are preferable.
- Output is a snapshot and can change immediately.

## 5. Important commands

| Command | Purpose | Risk |
|---|---|---|
| `sudo lsof` | List all visible open files. | Read-only |
| `sudo lsof /var/log/messages` | Show processes holding a path. | Read-only |
| `sudo lsof +D /var/log/myapp` | Recursively scan a directory tree. | Read-only |
| `sudo lsof +f -- /data` | Show open files on a mounted filesystem. | Read-only |
| `sudo lsof +L1` | Find deleted files that remain open. | Read-only |
| `sudo lsof -p 1234` | List files opened by one PID. | Read-only |
| `sudo lsof -u appuser` | List files opened by a user. | Read-only |
| `sudo lsof -i` | List Internet sockets. | Read-only |
| `sudo lsof -iTCP:443 -sTCP:LISTEN -nP` | Find TCP listeners on port 443. | Read-only |
| `sudo lsof -iTCP -sTCP:ESTABLISHED -nP` | List established TCP sockets. | Read-only |
| `sudo lsof -U` | List Unix-domain sockets. | Read-only |
| `sudo lsof -a -p 1234 -d 0-20` | Combine PID and descriptor filters. | Read-only |
| `sudo lsof -Fn0 -p 1234` | Produce field-oriented, NUL-safe output for scripts. | Read-only |

## 7. Output interpretation

- `FD` identifies descriptors and special references such as `cwd`, `rtd`, `txt`, and memory maps.
- `DEL` or a `(deleted)` name can explain `df` versus `du` differences.
- `TYPE` can be REG, DIR, IPv4, IPv6, unix, FIFO, CHR, BLK, and others.
- `NODE` and device identifiers can be mapped back to filesystem inodes.
- A busy mount may be held by a shell current directory rather than an ordinary file descriptor.

## 8. Corporate/L3 troubleshooting workflow

1. **Confirm impact:** Record affected applications, users, start time, error rate, latency, and business severity.
2. **Identify scope:** Determine whether the issue is host-wide, process-specific, filesystem-specific, network-path-specific, or limited to one namespace.
3. **Preserve evidence:** Save logs, configuration, counters, command output, package versions, and timestamps before changing state.
4. **Establish ownership:** Identify whether systemd, NetworkManager, firewalld, TuneD, udev, a backup scheduler, configuration management, or the application owns the setting.
5. **Use read-only inspection first:** Confirm the hypothesis with at least two independent evidence sources.
6. **Control the test:** Make only one bounded change and define the rollback command in advance.
7. **Measure service behavior:** Validate latency, throughput, errors, data consistency, authentication, and client experience.
8. **Persist correctly:** Apply successful changes through the supported configuration source rather than an ad hoc runtime command.
9. **Close the incident:** Document root cause, contributing conditions, corrective action, monitoring, and prevention.

## 9. Production cautions

- Recursive `+D` scans can be expensive.
- Do not kill a process solely because it holds a deleted log; determine service impact and use the correct reopen/restart method.
- Protect output because it exposes paths, processes, and network topology.
- Prefer `ss` for high-volume socket analysis and use `lsof` for ownership correlation.
- Replace all example users, paths, devices, addresses, ports, repositories, and services only after validation.
- Keep console or out-of-band access for firewall, bootloader, storage, authentication, and network changes.
- Back up data and configuration before destructive, recursive, or boot-critical commands.

## 10. Practice lab

1. Open a file in an editor.
2. Delete it from another shell.
3. Find it with `lsof +L1`.
4. Close the descriptor.
5. Verify filesystem space is released.
