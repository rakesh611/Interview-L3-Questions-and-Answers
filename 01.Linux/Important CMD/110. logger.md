# 110. logger

> **Level:** Linux Corporate/L3 administration and troubleshooting.

## 1. What it is

`logger` writes messages to the system logging service or journal. It is useful for testing rsyslog routes, creating operational markers, adding structured identifiers, and sending controlled remote syslog tests.

## 2. Why it matters in production

- Provides a repeatable method to inspect, validate, or control an important Linux subsystem.
- Produces evidence that can be attached to incident, change, problem, audit, and capacity records.
- Helps distinguish configuration, permission, kernel, service, network, storage, security, and application failures.
- Supports before-and-after validation rather than unmeasured configuration changes.

## 4. Core concepts

- Syslog priority combines facility and severity.
- The tag or identifier helps filters and searches distinguish a test message.
- Local logging may be handled by journald, rsyslog, or both.
- Remote delivery can use UDP, TCP, or TLS depending on the logging stack.
- A locally accepted message is not proof that it reached a remote collector.
- Structured fields and RFC formats depend on the implementation and destination.

## 5. Important commands

| Command | Purpose | Operational risk |
|---|---|---|
| `logger 'maintenance test message'` | Write a default-priority message. | Read-only |
| `logger -t myapp 'application test event'` | Set a tag/identifier. | Read-only |
| `logger -p authpriv.notice -t access-test 'controlled authentication test'` | Set facility and severity. | Read-only |
| `logger --id=$$ -t shell-test 'message with process ID'` | Include a process ID. | Read-only |
| `printf 'line one\nline two\n' \| logger -t multiline` | Log standard input. | Read-only |

| `logger -n loghost.example.com -P 514 -d -t remote-test 'UDP test'` | Send a UDP syslog test. | Network test |
| `logger -n loghost.example.com -P 514 -T -t remote-test 'TCP test'` | Send a TCP syslog test. | Network test |

## 7. How to interpret the output

- Facility helps route broad message categories; severity supports filtering and alerting.
- The journal can retain metadata not present in plain syslog files.
- Duplicate messages can occur when journald forwards to rsyslog and another route re-ingests them.
- Missing remote messages require sender queue, network, TLS, receiver, and filter checks.

## 8. L3 troubleshooting workflow

1. **Define impact:** Identify the affected service, users, start time, scope, and business symptom.
2. **Preserve evidence:** Capture relevant logs, configuration, counters, timestamps, versions, and current state.
3. **Confirm ownership:** Determine whether systemd, NetworkManager, authselect, firewalld, policy, automation, or another manager owns the configuration.
4. **Use read-only checks first:** Avoid changing state before the failure mode is understood.
5. **Correlate adjacent layers:** Check process, kernel, filesystem, network, DNS, time, identity, audit, and SELinux evidence as appropriate.
6. **Form one hypothesis:** State what evidence supports it and what observation would disprove it.
7. **Make one controlled change:** Use a maintenance window, backup, console path, and rollback command.
8. **Validate service metrics:** Confirm application latency, error rate, authentication, data integrity, and logs—not only command success.
9. **Restore or persist:** Roll back failed experiments and make successful changes through approved configuration management.
10. **Document RCA:** Record root cause, contributing factors, corrective action, prevention, and monitoring.

## 9. Production cautions

- Do not log passwords, private keys, tokens, personal data, or confidential payloads.
- Rate-limit test floods and use a unique tag.
- Coordinate remote tests with the SIEM or logging team.
- UDP delivery is not reliable and can lose messages silently.
- Never copy example users, paths, ports, addresses, or devices into production without validation.
- Commands that change credentials, access, labels, firewall rules, packages, audit rules, or services require change control.
- Keep an independent administrative path for SSH, PAM, firewall, DNS, and authentication work.

## 10. Quick practice lab

1. Send messages at several priorities.
2. Find them in the journal.
3. Create a temporary rsyslog filter for a unique tag.
4. Test TCP delivery to a lab collector.
5. Remove the filter and confirm no residual queue.
