# How Central and Secured Cluster Components Interact in Red Hat Advanced Cluster Security (RHACS)

## Overview

Red Hat Advanced Cluster Security (RHACS) uses a **Centralized Security Management** architecture. The platform consists of two major parts:

1. **Central** – The management and policy engine.
2. **Secured Cluster** – The security components deployed inside each Kubernetes or OpenShift cluster.

Together, they continuously monitor applications from **build → deployment → runtime**.

# Main Components

| Component | Location | Purpose |
|----------|----------|----------|
| Central | Separate management cluster or SNO | Security management platform |
| Sensor | Every secured cluster | Watches Kubernetes resources |
| Collector | Every cluster node | Monitors runtime container activity |
| Admission Controller | Every cluster | Blocks risky deployments |
| Scanner (Optional) | Central or remote | Scans container images |

# Step-by-Step Interaction

## Step 1 — Cluster Registration

A secured cluster is registered with Central.

```text
Administrator

      |

      v

Generate Init Bundle

      |

      v

Deploy Sensor into Cluster

      |

      v

Secure TLS Connection Created
```

Commands:

```bash
# Download init bundle from Central

# Deploy Sensor
oc apply -f init-bundle.yaml
```

## Step 2 — Sensor Connects to Central

<image_placeholder>

The Sensor:

- Authenticates using certificates.
- Opens an encrypted connection.

## Step 7 — Policy Evaluation

| Policy | Action |
|--------|--------|

# Key Takeaways

- **Central** is the management, analytics, policy, and reporting engine.
- **Sensor** watches Kubernetes resources and communicates with Central.
- **Collector** monitors runtime activity on every node.
- **Admission Controller** prevents insecure deployments before they start.
- **Scanner** identifies vulnerabilities in container images.
- Communication between Central and secured clusters is protected using **mutual TLS (mTLS)**.
- Together, these components provide continuous security across the **Build → Deploy → Runtime** lifecycle.
