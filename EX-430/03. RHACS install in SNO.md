# RHACS on Single-Node OpenShift (SNO) — From Scratch

> **Product name:** Red Hat Advanced Cluster Security for Kubernetes (**RHACS**).  
> This guide assumes “RHCAS” means **RHACS**.
>
> **Target architecture:** One OpenShift Single-Node OpenShift (SNO) cluster hosts both:
> - RHACS Central
> - RHACS Scanner
> - RHACS secured-cluster services (Sensor, Admission Controller, Collector, Scanner-slim)
>
> This is suitable for a lab, PoC, training, or small environment. For production, validate RHACS and SNO support, sizing, storage, backup, and availability requirements against the exact OpenShift/RHACS versions you intend to run.

---

## 1. Architecture

```text
                         Users / Admin
                              |
                              | HTTPS
                              v
                    +----------------------+
                    | OpenShift SNO        |
                    |                      |
                    |  RHACS Operator      |
                    |       |              |
                    |       v              |
                    |  +-----------+       |
                    |  |  Central  |       |
                    |  +-----------+       |
                    |       |              |
                    |       +--> Scanner    |
                    |                      |
                    |  SecuredCluster      |
                    |       |              |
                    |       +--> Sensor     |
                    |       +--> Admission  |
                    |       +--> Collector  |
                    |       +--> Scanner-   |
                    |            slim       |
                    +----------------------+
```

Because this is SNO, the same cluster is both the **Central cluster** and the **secured cluster**.

# 2. What You Need Before Starting

## 2.1 OpenShift requirements

You need:

- A working OpenShift Container Platform SNO cluster.
- `cluster-admin` access.
- A supported OpenShift version for the RHACS release you select.
- Working DNS.
- Working HTTPS access to the OpenShift API and console.
- Internet access to Red Hat registries, unless you have configured a disconnected/mirrored environment.
- Sufficient CPU, memory, and persistent storage for OpenShift plus RHACS.

Check the cluster:

```bash
oc version
oc whoami
oc whoami --show-server
oc get clusterversion
oc get nodes -o wide
```

Confirm administrator access:

```bash
oc auth can-i '*' '*' --all-namespaces
```

Expected:

```text
yes
```

Check that the node is Ready:

```bash
oc get nodes
```

Example:

```text
NAME       STATUS   ROLES                         AGE   VERSION
sno01      Ready    control-plane,master,worker   10d   v4.x.x
```

# 3. If SNO Does Not Exist Yet

If you already have a working SNO cluster, skip this section and continue with **Section 4**.

Red Hat supports installing SNO using the Assisted Installer or other documented SNO installation methods.

For a new SNO deployment, collect these values first:

```text
Cluster name:       sno
Base domain:        example.com
API VIP:             192.168.10.10
Ingress VIP:         192.168.10.11
Node IP:             192.168.10.20
Gateway:             192.168.10.1
DNS server:          192.168.10.1
```

Your real values will be different.

The resulting DNS names normally include:

```text
api.<cluster>.<base-domain>
*.apps.<cluster>.<base-domain>
```

For example:

```text
api.sno.example.com
console-openshift-console.apps.sno.example.com
```

After SNO installation, verify:

```bash
oc get clusterversion
oc get nodes
oc get co
```

All critical ClusterOperators should eventually report healthy:

```text
AVAILABLE=True
PROGRESSING=False
DEGRADED=False
```

Useful command:

```bash
oc get co
```

Do not start the RHACS installation while the OpenShift cluster itself is unhealthy.

# 5. Check SNO Resources Before Installing RHACS

RHACS adds additional workloads to the only node, so check capacity first.

```bash
oc describe node
```

Check CPU and memory requests:

```bash
oc describe node | egrep -A10 "Capacity|Allocatable|Allocated resources"
```

Check storage:

```bash
oc get storageclass
oc get pv
oc get pvc -A
```

Check current pods:

```bash
oc get pods -A
```

Check disk usage on the SNO node:

```bash
oc debug node/$(oc get nodes -o jsonpath='{.items[0].metadata.name}') -- chroot /host df -h
```

Do not continue if the node is already critically short on CPU, memory, or disk.

# 12. Create the Central Custom Resource

Because this is the first RHACS installation, install **Central first**. The secured-cluster resources depend on certificates and information generated by Central.

A simple starting CR is:

```yaml
apiVersion: platform.stackrox.io/v1alpha1
kind: Central
metadata:
  name: central
  namespace: stackrox
spec:
  central:
    exposure:
      route:
        enabled: true
```

Save as:

```text
central.yaml
```

Apply it:

```bash
oc apply -f central.yaml
```

Verify:

```bash
oc get central -n stackrox
```

Watch the RHACS pods:

```bash
oc get pods -n stackrox -w
```

Wait until the Central-related pods become Ready.

# 16. Generate a Cluster Registration Secret

Because the SNO cluster itself will be secured by its own Central, you must now configure the secured-cluster services.

In the RHACS console, go to the cluster/secured-cluster installation workflow.

Generate a:

```text
Cluster Registration Secret (CRS)
```

The CRS is the preferred registration mechanism.

Download the generated YAML.

For example:

```text
sno-cluster-registration.yaml
```

Keep this file secure.

Ensure you are logged into the same SNO cluster:


```bash
oc create -f sno-cluster-registration.yaml -n stackrox
```

Verify:

```bash

```

If you receive:

```text
already exists
```

do not blindly delete the existing secret. Check whether it belongs to the intended RHACS installation.

---

# 18. Create the SecuredCluster Custom Resource

Create:

```text
securedcluster.yaml
```

Use the Central endpoint generated by your RHACS installation.

Example structure:

```yaml
apiVersion: platform.stackrox.io/v1alpha1
kind: SecuredCluster
metadata:
  name: stackrox-secured-cluster-services
  namespace: stackrox
spec:
  clusterName: sno
  centralEndpoint: central.stackrox.svc:443
```

Important:

The exact `SecuredCluster` schema and Central endpoint settings can vary by RHACS release. Before applying this file, use the CR schema exposed by the Operator installed in your cluster:

```bash
oc explain securedcluster.spec
```

Also inspect:

```bash
oc explain securedcluster.spec.centralEndpoint
```

If your Operator exposes different required fields, use those fields rather than copying an older example.

Apply:

```bash
oc apply -f securedcluster.yaml
```

# 33. Troubleshooting — Central Stuck Pending

Check:

```bash
oc get pods -n stackrox
```

Describe the pending pod:

```bash
oc describe pod <pod-name> -n stackrox
```

Look at the Events section.

Check node resources:

```bash
oc describe node
```

Check:

```bash
oc adm top node
```

Common causes on SNO:

- Insufficient memory.
- Insufficient CPU.
- Storage unavailable.
- PVC cannot bind.
- Taints/tolerations mismatch.
- Image pull failure.
- Registry authentication failure.
