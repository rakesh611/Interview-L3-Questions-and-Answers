# Which Namespace Should Host the RHACS Operator?

## Short Answer

The **RHACS Operator should normally be installed in the `rhacs-operator` namespace**.

```text
rhacs-operator
└── RHACS Operator
```

This namespace is dedicated to the RHACS Operator itself.

The RHACS Central components are normally deployed separately, commonly in the:

```text
stackrox
```

namespace.

---

## 1. Recommended Namespace Layout

A typical RHACS deployment on OpenShift looks like this:

```text
OpenShift Cluster
│
├── rhacs-operator
│   └── RHACS Operator
│
└── stackrox
    ├── Central
    ├── Scanner
    ├── Scanner V4
    └── Other RHACS components
```

The important distinction is:

```text
rhacs-operator
        │
        └── Operator that manages RHACS

stackrox
        │
        └── RHACS Central and related components
```

Do not confuse the Operator namespace with the Central namespace.

---

# 2. Why Use `rhacs-operator`?

Using a dedicated namespace provides several operational advantages.

### Separation of Responsibilities

The Operator is separated from the RHACS workloads it manages.

```text
Operator
   │
   ▼
rhacs-operator

RHACS workloads
   │
   ▼
stackrox
```

This makes it easier for administrators to:

* Troubleshoot the Operator.
* Monitor Operator resources.
* Review Operator logs.
* Manage RBAC.
* Review namespace-specific events.
* Apply organizational policies.

---

# 3. Create the Namespace

If it does not already exist:

```bash
oc create namespace rhacs-operator
```

Verify:

```bash
oc get namespace rhacs-operator
```

Expected:

```text
NAME             STATUS   AGE
rhacs-operator   Active   ...
```

---

# 4. Install the Operator into `rhacs-operator`

When installing the RHACS Operator from **OperatorHub**, select:

```text
Installation Mode:
    All namespaces on the cluster

Installed Namespace:
    rhacs-operator
```

The conceptual configuration is:

```text
OperatorHub
     │
     ▼
RHACS Operator
     │
     ▼
rhacs-operator
```

The exact installation options can vary slightly depending on the OpenShift and RHACS versions available in your environment.

---

# 5. Verify the Operator Namespace

After installation:

```bash
oc get pods -n rhacs-operator
```

Example:

```text
NAME                                             READY   STATUS    RESTARTS   AGE
rhacs-operator-controller-manager-xxxxx-xxxxx   1/1     Running   0          5m
```

Check deployments:

```bash
oc get deployment -n rhacs-operator
```

Check the Operator:

```bash
oc get csv -n rhacs-operator
```

A healthy CSV should eventually show:

```text
PHASE
Succeeded
```

---

# 6. Check the Subscription

The Operator's Subscription should also be in the Operator namespace:

```bash
oc get subscription -n rhacs-operator
```

For more information:

```bash
oc describe subscription -n rhacs-operator
```

This helps verify:

* Selected channel.
* Installed version.
* Catalog source.
* InstallPlan.
* Approval strategy.

---

# 7. Check the InstallPlan

Run:

```bash
oc get installplan -n rhacs-operator
```

If manual approval is configured:

```bash
oc describe installplan <installplan-name> \
  -n rhacs-operator
```

The InstallPlan is an OLM resource associated with installing or updating the Operator.

---

# 8. Operator Namespace vs Central Namespace

This is one of the most important concepts to understand.

| Resource             | Typical Namespace | Purpose                        |
| -------------------- | ----------------- | ------------------------------ |
| RHACS Operator       | `rhacs-operator`  | Manages RHACS resources        |
| RHACS Central        | `stackrox`        | Central RHACS management plane |
| RHACS Scanner        | `stackrox`        | Image vulnerability scanning   |
| RHACS Sensor         | Secured cluster   | Monitors secured cluster       |
| Admission Controller | Secured cluster   | Admission-time enforcement     |
| Collector            | Secured cluster   | Runtime/network security data  |

The exact RHACS components and namespace placement can vary by RHACS version and deployment configuration.

---

# 9. Why Not Install the Operator in `stackrox`?

It is important to understand that:

```text
stackrox
```

is generally used for the RHACS Central workload, whereas:

```text
rhacs-operator
```

is the dedicated namespace for the Operator.

Keeping them separate provides a cleaner architecture:

```text
                 OpenShift
                     │
          ┌──────────┴──────────┐
          │                     │
          ▼                     ▼
 rhacs-operator              stackrox
          │                     │
          ▼                     ▼
   RHACS Operator         RHACS Central
                                │
                    ┌───────────┼───────────┐
                    ▼           ▼           ▼
                 Scanner     Scanner V4   Other services
```

---

# 10. Operator Installation Does Not Automatically Mean Central Is Installed

Installing:

```text
RHACS Operator
```

in:

```text
rhacs-operator
```

does not by itself mean that RHACS Central has been deployed.

The workflow is:

```text
1. Install RHACS Operator
          │
          ▼
2. rhacs-operator
          │
          ▼
3. Create RHACS Central resource
          │
          ▼
4. Central is deployed
          │
          ▼
5. RHACS UI becomes available
```

Therefore, always distinguish:

```text
Operator installation
        ≠
Central installation
```

# 12. Troubleshooting

## Operator Pod Not Running

Check:

```bash
oc get pods -n rhacs-operator
```

Then:

```bash
oc describe pod <pod-name> -n rhacs-operator
```

Check logs:

```bash
oc logs <pod-name> -n rhacs-operator
```

---

## CSV Not Succeeded

Run:

```bash
oc get csv -n rhacs-operator
```

Then:

```bash
oc describe csv <csv-name> -n rhacs-operator
```

Check namespace events:

```bash
oc get events \
  -n rhacs-operator \
  --sort-by='.lastTimestamp'
```

---

## Subscription Not Progressing

Run:

```bash
oc describe subscription \
  -n rhacs-operator
```

Then inspect:

```bash
oc get installplan -n rhacs-operator
```

If the InstallPlan requires manual approval, review and approve it according to your organization's change-control process.

---

# 13. Enterprise Recommendation

For an enterprise OpenShift environment, use a dedicated namespace:

```text
rhacs-operator
```

for the RHACS Operator.

Use a separate namespace, typically:

```text
stackrox
```

for RHACS Central.

Recommended model:

```text
                    RHACS Central Cluster
                            │
             ┌──────────────┴──────────────┐
             │                             │
             ▼                             ▼
      rhacs-operator                    stackrox
             │                             │
             │                             ├── Central
             │                             ├── Scanner
             │                             └── Other RHACS services
             │
             └── RHACS Operator
```

This provides a clean separation between **Operator lifecycle management** and the **RHACS Central workload**.

# 14. Interview Answer

### Question

**Which namespace should host the RHACS Operator?**

### Answer

The RHACS Operator should normally be installed in the dedicated:

```text
rhacs-operator
```

namespace.

The Operator manages RHACS custom resources and lifecycle operations. RHACS Central is normally deployed separately, commonly in the:

```text
stackrox
```

namespace.

Therefore:

```text
rhacs-operator → RHACS Operator

stackrox       → RHACS Central
```

Keeping these separate makes RHACS administration, troubleshooting, RBAC, monitoring, and lifecycle management easier.
