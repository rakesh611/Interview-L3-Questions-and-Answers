# Red Hat Advanced Cluster Security (RHACS) – Problems It Solves

## 1. Overview

**Red Hat Advanced Cluster Security for Kubernetes (RHACS)** is a Kubernetes and OpenShift security platform that provides security visibility, policy enforcement, vulnerability management, compliance monitoring, network security, and runtime threat detection.

RHACS protects applications across the complete container lifecycle:

```text
Build → Deploy → Runtime
```

It can be used with Red Hat OpenShift as well as Kubernetes environments.

---

# 2. What Problems Does RHACS Solve?

RHACS primarily solves the following security problems:

| Problem | RHACS Solution |
|---|---|
| Vulnerable container images | Scans images for known vulnerabilities/CVEs |
| Insecure Kubernetes configuration | Detects security configuration problems |
| Excessive container privileges | Identifies privileged containers and dangerous capabilities |
| Unauthorized or risky deployments | Enforces deployment security policies |
| Runtime attacks | Detects suspicious behavior in running workloads |
| Lateral movement | Provides network visibility and segmentation capabilities |
| Supply-chain security | Performs security checks before workloads reach production |
| Compliance problems | Provides security/compliance assessments |
| Poor security visibility | Centralizes security information across clusters |
| Security policy violations | Detects and can enforce policy violations |
| Excessive risk | Provides risk prioritization for workloads |
| Incident investigation | Provides security events and runtime information |

---

# 3. Vulnerability Management

One major problem in Kubernetes environments is that container images may contain vulnerable packages.

Example:

```text
Developer
   |
   v
Application
   |
   v
Container Image
   |
   +---- OpenSSL CVE
   +---- Log4j CVE
   +---- Kernel/package vulnerability
   |
   v
Container Registry
   |
   v
OpenShift
```

Without proper security scanning, a vulnerable image could reach production.

RHACS can scan container images and identify known vulnerabilities.

Example:

```text
payment:v2.5
     |
     +-- Critical CVE
     +-- High CVE
     +-- Medium CVE
```

Security teams can then prioritize the vulnerabilities that create the greatest risk.

---

# 4. Insecure Kubernetes/OpenShift Configuration

A workload can be vulnerable even when its container image has no known CVE.

For example:

```yaml
securityContext:
  privileged: true
```

Other risky configurations may include:

- Privileged containers
- Host network usage
- Host PID namespace
- Host filesystem mounts
- Excessive Linux capabilities
- Running as root
- Insecure container configuration
- Weak Kubernetes permissions
- Risky deployment configurations

RHACS helps identify these security weaknesses and can enforce policies against them.

Consider a production environment:

```text

 |

 v

 |
 v

```

A developer deploys an application that violates company security policy.

For example:

```text

    privileged = true
```

or:

```text
Container:
    runs as root
```

or:

```text

    contains critical vulnerability
```

RHACS can detect the violation and, depending on the configured policy and enforcement stage, prevent the deployment from reaching production.

Conceptually:

```text
Developer
    |
    v
CI/CD
    |
    v
RHACS Policy Check
    |
    +---- PASS ----> OpenShift
    |
    +---- FAIL ----> Deployment blocked
```

# 6. Runtime Security

Security does not stop after deployment.

A container may initially be safe but later become compromised.

For example:

```text
payment-pod
     |
     +-- Normal:
     |      application process
     |
     +-- Suspicious:
            /bin/sh
            curl
            wget
            unexpected process
```

RHACS provides runtime visibility and can detect suspicious container behavior based on security policies and observed activity.

This helps security teams investigate possible attacks after workloads are already running.

---

# 7. Detecting Suspicious Container Behavior

Suppose a web application normally communicates with:

```text
Web Pod
   |
   v
Application Pod
   |
   v
Database
```

Suddenly the application pod starts communicating with an unknown external destination:

```text
Application Pod
       |
       +----> Database
       |
       +----> Unknown Internet IP
```

This could indicate:

- Compromise
- Malware
- Command-and-control communication
- Data exfiltration
- Misconfiguration

RHACS provides visibility into workload behavior and network communication to help security teams identify such activity.

---

# 8. Network Security and Lateral Movement

A compromised pod may attempt to move laterally inside the cluster.

Example:

```text
Compromised Web Pod
       |
       +----> API Server
       |
       +----> Database
       |
       +----> Other Application
       |
       +----> Internal Services
```

This creates a major security risk.

RHACS provides network visibility and helps organizations understand:

```text
Who communicates with whom?
```

For example:

```text
Frontend
   |
   v
Backend
   |
   v
Database
```

Security teams can use this information to design and enforce appropriate network segmentation.

Modern applications depend on:

```text
Source Code
     |
     v

     |
     v
Build
     |
     v

     |
     v

     |
```

Security problems can enter at any point.

Examples:

- Vulnerable dependencies
- Vulnerable base images
- Untrusted images
- Misconfigured builds

RHACS helps provide security controls around container images and deployments.

The objective is:


# 11. Security Risk Prioritization

Large OpenShift environments may contain:

```text
10+ Clusters
100+ Namespaces
1000+ Pods
1000+ Container Images
```

Security teams can receive a very large number of findings.

The problem is:

> Which vulnerability or workload should be fixed first?

RHACS provides risk information to help prioritize security issues.

Example:

```text
Application A
Critical CVE + Internet exposed + Privileged
        |
        v
       HIGH RISK
```

Compared with:

```text
Application B
Medium CVE + Internal only + Restricted
        |
        v
      LOWER RISK
```

This allows security teams to focus on the highest-risk workloads first.

# 13. Security Policy Enforcement

RHACS allows organizations to define security policies.

Example corporate policy:

```text
Production containers must NOT:

1. Run privileged
2. Run as root
3. Use host network
4. Use host PID
5. Add dangerous capabilities
6. Use unapproved images
7. Deploy images with critical vulnerabilities
```

Conceptually:

```text
                    RHACS
                      |
             Security Policies
                      |
       +--------------+--------------+
       |              |              |
       v              v              v
     Build          Deploy         Runtime
       |              |              |
       v              v              v
   Check Image    Check Config   Detect Threat
```

# 14. Build-Time Security

Security can be introduced into the CI/CD pipeline.

Example:

```text
Developer
    |
    v
Git
    |
    v
Jenkins
    |
    v
Build Image
    |
    v
RHACS Security Check
    |
    +---- PASS ----> Registry
    |
    +---- FAIL ----> Pipeline/Build blocked
```

This is an example of **Shift Left Security**.

Instead of finding a security problem after production deployment, the organization attempts to detect it earlier.

---

# 15. Deployment-Time Security

At deployment time, RHACS can evaluate Kubernetes/OpenShift workloads against configured security policies.

Example:

```text
Deployment YAML
      |
      v
RHACS Policy Evaluation
      |
      +---- PASS
      |      |
      |      v
      |   Production
      |
      +---- FAIL
             |
             v
        Security Alert
        / Enforcement
```

Possible checks include:

- Image vulnerability
- Privileged container
- Host namespace
- Container capabilities
- Security context
- Deployment configuration
- Kubernetes security requirements

# 16. Runtime Threat Detection

Runtime security is important because an attacker may compromise an already deployed application.

Example:

```text
Normal Application
        |
        v
Production Pod
        |
        X
     Compromise
        |
        v
Unexpected Activity
```

RHACS can provide visibility into runtime behavior and security events.

Examples of suspicious activity may include:

- Unexpected process execution
- Unexpected network communication
- Container behavior violating policy
- Suspicious system activity

# 18. RHACS vs OpenShift Native Security

OpenShift already provides many security controls.

For example:

```text
OpenShift
|
+-- RBAC
+-- SCC
+-- NetworkPolicy
+-- OAuth
+-- Secrets
+-- TLS
+-- Admission controls
```

These controls are essential, but RHACS adds a broader security-management and visibility layer.

Think of it as:

```text
OpenShift Native Security
        +
RHACS Security Platform
        |
        v
Build + Deploy + Runtime Security
```
