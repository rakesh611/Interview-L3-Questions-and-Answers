# How Do Automatic and Manual InstallPlan Approval Differ?

## 1. Overview

When an Operator is installed through **Operator Lifecycle Manager (OLM)**, OLM creates an **InstallPlan** that describes the resources and actions required to install or update the Operator.

The InstallPlan can use one of two approval strategies:

```text
Automatic
Manual
```

The main difference is **who approves the InstallPlan before OLM proceeds with the installation or upgrade**.

```text
Automatic:
Subscription
      ↓
InstallPlan
      ↓
Automatically approved
      ↓
Operator installed/upgraded

Manual:
Subscription
      ↓
InstallPlan
      ↓
Waiting for administrator approval
      ↓
Administrator approves
      ↓
Operator installed/upgraded
```

---

# 2. Automatic Approval

With **automatic approval**, OLM automatically approves the InstallPlan when it determines that the requested Operator installation or update can proceed.

The workflow is:

```text
OperatorHub
     │
     ▼
Subscription
     │
     ▼
InstallPlan
     │
     ▼
Automatic approval
     │
     ▼
CSV installed
     │
     ▼
Operator deployed
```

The administrator does not need to manually approve every InstallPlan.

---

# 3. Automatic Approval Example

A Subscription may specify:

```yaml
spec:
  installPlanApproval: Automatic
```

The exact Subscription configuration should match the Operator and OpenShift version being used.

Check the current Subscription:

```bash
oc get subscription -n rhacs-operator
```

Inspect it:

```bash
oc get subscription rhacs-operator \
  -n rhacs-operator \
  -o yaml
```

Look for:

```yaml
spec:
  installPlanApproval: Automatic
```

---

# 4. What Happens With Automatic Approval?

Suppose a new RHACS Operator version becomes available.

The sequence is:

```text
New Operator version available
             │
             ▼
Subscription detects update
             │
             ▼
OLM creates InstallPlan
             │
             ▼
InstallPlan automatically approved
             │
             ▼
CSV installed/updated
             │
             ▼
RHACS Operator upgraded
```

This reduces administrative effort.

---

# 5. Advantages of Automatic Approval

### Faster Updates

Operators can be installed or updated without waiting for administrator approval.

### Less Operational Work

Administrators do not need to monitor every InstallPlan.

### Useful for Development/Lab Environments

Automatic approval is convenient for:

```text
Development
Testing
Home Lab
Non-critical environments
```

### Continuous Lifecycle Management

OLM can continuously maintain the Operator according to the selected channel and update policy.

---

# 6. Disadvantages of Automatic Approval

Automatic approval also has risks.

For example:

```text
New Operator version
        │
        ▼
Automatic approval
        │
        ▼
Operator upgrade
```

There may be no manual change-control checkpoint before the upgrade.

Potential concerns include:

* Unexpected Operator upgrades.
* Compatibility considerations.
* Changes to Operator behavior.
* Changes to managed resources.
* Need for application testing before upgrades.
* Change-management requirements.

Therefore, automatic approval should be selected according to the organization's lifecycle and change-management policy.

---

# 7. Manual Approval

With **manual approval**, OLM creates the InstallPlan but waits for an administrator to approve it.

The workflow is:

```text
Subscription
     │
     ▼
InstallPlan
     │
     ▼
Waiting for approval
     │
     ▼
Administrator reviews
     │
     ▼
Administrator approves
     │
     ▼
CSV installed/updated
     │
     ▼
Operator deployed/upgraded
```

This gives administrators an explicit control point.

---

# 8. Manual Approval Example

A Subscription may specify:

```yaml
spec:
  installPlanApproval: Manual
```

Check:

```bash
oc get subscription rhacs-operator \
  -n rhacs-operator \
  -o yaml
```

Look for:

```yaml
spec:
  installPlanApproval: Manual
```

---

# 9. What Happens With Manual Approval?

Suppose a new RHACS Operator version becomes available.

OLM performs:

```text
New version available
        │
        ▼
Subscription
        │
        ▼
InstallPlan created
        │
        ▼
APPROVED = false
        │
        ▼
Wait
```

The administrator then reviews the InstallPlan.

After approval:

```text
APPROVED = true
        │
        ▼
OLM performs installation/update
        │
        ▼
CSV becomes active
        │
        ▼
Operator upgraded
```

---

# 10. Check InstallPlan Status

Run:

```bash
oc get installplan -n rhacs-operator
```

Example:

```text
NAME            CSV                         APPROVAL   APPROVED
install-xxxxx   rhacs-operator.v4.x.x      Manual     false
```

This means the InstallPlan is waiting for administrator approval.

---

# 11. Inspect the InstallPlan

Run:

```bash
oc describe installplan <installplan-name> \
  -n rhacs-operator
```

Review:

```text
Status
Conditions
ClusterServiceVersionNames
Plan
Events
```

Before approving a production upgrade, verify:

* Target Operator version.
* Upgrade path.
* Dependencies.
* Supported OpenShift version.
* RHACS compatibility.
* Organizational change ticket.
* Maintenance window.
* Backup/recovery requirements.
* Application impact.

---

# 12. Approve the InstallPlan

After the change has been reviewed and approved according to organizational procedures:

```bash
oc patch installplan <installplan-name> \
  -n rhacs-operator \
  --type merge \
  -p '{"spec":{"approved":true}}'
```

Verify:

```bash
oc get installplan -n rhacs-operator
```

You should see:

```text
NAME            CSV                         APPROVAL   APPROVED
install-xxxxx   rhacs-operator.v4.x.x      Manual     true
```

Then monitor the CSV:

```bash
oc get csv -n rhacs-operator
```

# 13. Automatic vs Manual Approval

| Feature                              | Automatic         | Manual          |
| ------------------------------------ | ----------------- | --------------- |
| InstallPlan created                  | Yes               | Yes             |
| Approval required from admin         | No                | Yes             |
| Operator update starts automatically | Yes               | No              |
| Administrative control               | Lower             | Higher          |
| Deployment speed                     | Faster            | Slower          |
| Change-control checkpoint            | Limited           | Strong          |
| Suitable for lab                     | Yes               | Yes             |
| Suitable for production              | Depends on policy | Often preferred |
| Administrator review before update   | No                | Yes             |

For a corporate production environment, manual approval provides more control.

The review can include:

```text

        │
        ▼

        │

        │
```

---

# 17. Important Point: Manual Does Not Mean OLM Stops Managing the Operator

Manual approval does **not** disable OLM.

OLM continues to manage:

```text
Subscription
InstallPlan
CSV
Operator lifecycle
```

The difference is simply that OLM waits for an administrator to approve the InstallPlan before proceeding with the requested installation or upgrade.

---

# 18. Important Point: Manual Approval Is Not the Same as Blocking All Updates

Manual approval provides a decision point for InstallPlans.

After a new update is detected:

```text
Subscription
      │
      ▼
New InstallPlan
      │
      ▼
Waiting
```

The administrator decides when the InstallPlan should proceed.

This allows organizations to coordinate upgrades with:

* Maintenance windows.
* Application testing.
* Security reviews.
* Change-management procedures.
* Business requirements.

# 19. Troubleshooting Manual Approval

If the Operator appears stuck, first check:

```bash
oc get subscription -n rhacs-operator
```

Then:

```bash
oc get installplan -n rhacs-operator
```

Example:

```text
NAME            CSV                         APPROVAL   APPROVED
install-xxxxx   rhacs-operator.v4.x.x      Manual     false
```

If:

```text
APPROVED = false
```

the InstallPlan is waiting for approval.

Inspect it:

```bash
oc describe installplan <installplan-name> \
  -n rhacs-operator
```

After approval:

```bash
oc patch installplan <installplan-name> \
  -n rhacs-operator \
  --type merge \
  -p '{"spec":{"approved":true}}'
```

Monitor:

```bash
watch oc get csv,installplan \
  -n rhacs-operator
```

---

# 20. Troubleshooting Automatic Approval

If automatic approval is expected but the InstallPlan is not progressing, check the Subscription:

```bash
oc get subscription rhacs-operator \
  -n rhacs-operator \
  -o yaml
```

Verify:

```yaml
spec:
  installPlanApproval: Automatic
```

Then check:

```bash
oc get installplan -n rhacs-operator
```

Also inspect:

```bash
oc describe subscription rhacs-operator \
  -n rhacs-operator
```

and:

```bash
oc get events -n rhacs-operator \
  --sort-by='.lastTimestamp'
```

If the InstallPlan is approved but installation still fails, investigate the CSV:

```bash
oc get csv -n rhacs-operator
```

Then:

```bash
oc describe csv <csv-name> \
  -n rhacs-operator
```

# 23. Interview Questions

## Q1. What is the difference between automatic and manual InstallPlan approval?

**Answer:**

With automatic approval, OLM automatically approves the InstallPlan and proceeds with the Operator installation or upgrade.

With manual approval, OLM creates the InstallPlan but waits for an administrator to approve it.

```text
Automatic:
InstallPlan → Auto-approved → Install/Upgrade

Manual:
InstallPlan → Wait → Admin approval → Install/Upgrade
```

---

## Q2. Which approval strategy is better for production?

There is no universal rule, but **manual approval is often preferred in tightly controlled production environments** because it provides an explicit review and change-control checkpoint.

---

## Q3. Which approval strategy is convenient for a home lab?

**Automatic approval** is usually more convenient because Operator installation and updates can proceed without manual intervention.

---

## Q4. Does manual approval disable OLM?

**No.**

OLM continues to manage the Operator lifecycle. Manual approval simply requires administrator approval before the InstallPlan proceeds.

# 26. Final Takeaway

The fundamental difference is **control over when an InstallPlan is allowed to execute**.

```text
                 Subscription
                      │
                      ▼
                 InstallPlan
                      │
             ┌────────┴────────┐
             │                 │
             ▼                 ▼
        Automatic            Manual
             │                 │
             ▼                 ▼
       Auto-approved      Admin approval
             │                 │
             └────────┬────────┘
                      ▼
                     CSV
                      │
                      ▼
              Operator installed
```

**Automatic approval** provides speed and less administrative effort.

**Manual approval** provides stronger control and an explicit review point before Operator installation or upgrade.

For an RHACS production environment, choose the strategy according to your organization's change-management and upgrade policies; for a home lab, automatic approval is generally simpler.
