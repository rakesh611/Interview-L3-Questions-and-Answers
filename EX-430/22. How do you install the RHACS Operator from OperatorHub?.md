# How to Install the RHACS Operator from OperatorHub

## 1. Overview

Red Hat Advanced Cluster Security for Kubernetes (RHACS) can be installed on Red Hat OpenShift by using the **RHACS Operator** available through **OperatorHub**.

OperatorHub provides the discovery and installation interface, while **Operator Lifecycle Manager (OLM)** handles the installation, subscription, and lifecycle of the Operator.

The RHACS Operator is normally installed in the:

```text
rhacs-operator
```

namespace.

The Operator installation itself does **not** create the RHACS Central instance. After installing the Operator, you create the appropriate RHACS custom resource, such as `Central`, to deploy Central services.

A typical architecture is:

```text
                 OpenShift Cluster
                       │
                       ▼
              ┌─────────────────┐
              │   OperatorHub   │
              └────────┬────────┘
                       │
                       ▼
              RHACS Operator
              namespace:
              rhacs-operator
                       │
                       ▼
              ┌─────────────────┐
              │  RHACS Central  │
              │   namespace:    │
              │    stackrox     │
              └────────┬────────┘
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
       Secured Cluster 1   Secured Cluster 2
```

One RHACS Central can be used to secure multiple OpenShift or Kubernetes clusters.

---

## 2. Prerequisites

Before installing the RHACS Operator, verify:

* OpenShift cluster is running.
* You have access to the OpenShift web console.
* Your account has Operator installation permissions.
* The OpenShift cluster can access the Red Hat Operator catalog if it is connected to the internet.
* The RHACS version you intend to install is compatible with your OpenShift version.
* For production environments, use the RHACS version and channel recommended by Red Hat for your environment.

Check the cluster:

```bash
oc login https://api.cluster.example.com:6443
```

Verify cluster status:

```bash
oc get nodes
```

Example:

```text
NAME                 STATUS   ROLES                  AGE   VERSION
master01.example.com Ready    control-plane,master   10d   v1.xx.x
master02.example.com Ready    control-plane,master   10d   v1.xx.x
master03.example.com Ready    control-plane,master   10d   v1.xx.x
worker01.example.com Ready    worker                 10d   v1.xx.x
```

Verify the OpenShift version:

```bash
oc version
```

# 3. Create the RHACS Operator Namespace

Red Hat documentation uses the `rhacs-operator` namespace for the RHACS Operator.

You can create it before installation:

```bash
oc create namespace rhacs-operator
```

Verify:

```bash
oc get namespace rhacs-operator
```

Expected:

```text
NAME             STATUS   AGE
rhacs-operator   Active   ...
```

> Depending on the Operator installation workflow and OpenShift version, the namespace can also be created during the OperatorHub installation.

---

# 4. Open OperatorHub

Log in to the OpenShift web console.

Navigate to:

```text
Operators
   │
   └── OperatorHub
```

Alternatively, use the left-hand navigation:

```text
Home
  └── Operators
       └── OperatorHub
```

OperatorHub is the OpenShift interface for discovering and installing Operators.

---

# 5. Search for RHACS

In the **Filter by keyword** field, search for:

```text
Advanced Cluster Security
```

Look for:

```text
Red Hat Advanced Cluster Security for Kubernetes
```

Select the RHACS Operator.

Red Hat documentation specifically identifies **Red Hat Advanced Cluster Security for Kubernetes Operator** as the Operator to install for RHACS.

On the RHACS Operator page, review:

* Description
* Provider
* Version

* Installation modes
* Supported APIs

Before installing in production, verify that the selected RHACS Operator version is supported with your OpenShift version.

# 7. Click Install

Click:

```text
Install
```

OpenShift displays the **Install Operator** page.

You must configure the following important settings:

```text
Installation Mode
Update Channel
Installed Namespace
Update Approval
```

These are standard OperatorHub/OLM installation settings.

---

# 8. Configure Installation Mode

For RHACS, select:

```text
All namespaces on the cluster
```

This allows the Operator to watch the resources it needs across the cluster.

Red Hat's RHACS installation documentation uses:

```text
All namespaces on the cluster
```

for the Operator installation mode.

The conceptual configuration is:

```text
Installation Mode:
    All namespaces on the cluster
```

---

# 9. Select the Installed Namespace

For the RHACS Operator, use:

```text
rhacs-operator
```

Therefore:

```text
Installed Namespace:
    rhacs-operator
```

This separates the Operator itself from the namespace where RHACS Central services are deployed.

A common enterprise layout is:

```text
rhacs-operator
    └── RHACS Operator

stackrox
    └── RHACS Central
```

Red Hat documentation recommends installing the RHACS Operator into the `rhacs-operator` namespace.

---

# 10. Select the Update Channel

The available channels depend on the RHACS Operator catalog and version available to your OpenShift cluster.

For example:

```text
Update Channel:
    <supported RHACS channel>
```

Do not blindly select a channel only because it is the newest.

For production:

1. Check the RHACS support matrix.
2. Check your OpenShift version.
3. Check the RHACS version required by your organization.
4. Select the appropriate RHACS update channel.
5. Use the version recommended by your organization's lifecycle policy.

OperatorHub allows you to select a channel and, where supported, a specific Operator version.

---

# 11. Select Update Approval

You normally have two choices:

```text
Automatic
Manual
```

### Automatic

With automatic approval:

```text
New Operator version
        │
        ▼
       OLM
        │
        ▼
Automatic upgrade
```

This reduces administrative effort but means upgrades can occur without an administrator manually approving each update.

### Manual

With manual approval:

```text
New Operator version
        │
        ▼
       OLM
        │
        ▼
InstallPlan
        │
        ▼
Administrator approval
        │
        ▼
Upgrade
```

Manual approval is often preferable in tightly controlled enterprise environments because administrators can review an upgrade before allowing it.

OpenShift's Operator documentation confirms that automatic approval allows OLM to upgrade automatically, while manual approval requires administrator approval of the update request.

For a production RHACS environment, a reasonable governance approach is:

```text
Production:
    Manual approval

Lab:
    Automatic approval
```

# 17. Verify RHACS Custom Resources

After installing the Operator, check the CRDs:

```bash
oc get crd | grep -i stackrox
```

Depending on the RHACS version, you should see RHACS-related custom resource definitions.

You can also check API resources:

```bash
oc api-resources | grep -i stackrox
```

The important concept is:

```text
RHACS Operator
       │
       ├── Watches RHACS Custom Resources
       │
       ├── Creates RHACS resources
       │
       └── Manages RHACS lifecycle
```

---

# 18. Operator Installation Is Not the Same as RHACS Central Installation

This distinction is extremely important for RHACS administration and interviews.

Installing:

```text
RHACS Operator
```

does **not** automatically mean that RHACS Central has been deployed.

The workflow is:

```text
Step 1
Install RHACS Operator
        │
        ▼
Step 2
Create Central resource
        │
        ▼
Step 3
RHACS Central is deployed
        │
        ▼
Step 4
Access RHACS UI
        │
        ▼
Step 5
Register secured clusters
```

Red Hat's installation workflow describes installing the Operator first, then using it to install Central services in the `stackrox` project.

# 20. Troubleshooting Operator Installation

## Problem 1: RHACS Operator is not visible in OperatorHub

Check the Operator catalog:

```bash
oc get catalogsource -A
```

Look for:

```text
redhat-operators
```

Check its status:

```bash
oc get catalogsource -n openshift-marketplace
```

Example:

```text
NAME              DISPLAY            TYPE
redhat-operators  Red Hat Operators  grpc
```

If the catalog is unavailable, OperatorHub may not display the RHACS Operator.

Check:

```bash
oc get pods -n openshift-marketplace
```

---

## Problem 2: Subscription is stuck

Check:

```bash
oc get subscription -n rhacs-operator
```

Then:

```bash
oc describe subscription -n rhacs-operator
```

Look at:

```text
Conditions
Events
InstallPlan
CatalogSource
```

---

## Problem 3: InstallPlan is waiting for approval

Check:

```bash
oc get installplan -n rhacs-operator
```

Example:

```text
NAME            CSV                                      APPROVAL   APPROVED
install-xxxxx   rhacs-operator.v4.x.x                    Manual     false
```

If your organization's change-control process allows it, approve the InstallPlan:

```bash
oc patch installplan <installplan-name> \
  -n rhacs-operator \
  --type merge \
  -p '{"spec":{"approved":true}}'
```

Then monitor:

```bash
oc get installplan -n rhacs-operator
```

---

## Problem 4: CSV is not Succeeded

Check:

```bash
oc get csv -n rhacs-operator
```

Then:

```bash
oc describe csv <csv-name> -n rhacs-operator
```

Check:

```text
Conditions
Events
Requirements
InstallModes
```

Also check:

```bash
oc get events -n rhacs-operator \
  --sort-by='.lastTimestamp'
```

---

## Problem 5: Operator pod is CrashLoopBackOff

Check:

```bash
oc get pods -n rhacs-operator
```

Then:

```bash
oc describe pod <pod-name> -n rhacs-operator
```

Check logs:

```bash
oc logs <pod-name> -n rhacs-operator
```

If the pod has restarted:

```bash
oc logs <pod-name> \
  -n rhacs-operator \
  --previous
```

# 23. Important Interview Question

### Q: Does installing the RHACS Operator install RHACS completely?

**Answer: No.**

Installing the Operator installs the controller that manages RHACS resources.

The normal workflow is:

```text
OperatorHub
    │
    ▼
Install RHACS Operator
    │
    ▼
rhacs-operator namespace
    │
    ▼
Create Central resource
    │
    ▼
stackrox namespace
    │
    ▼
RHACS Central
    │
    ▼
Register secured clusters
```

One Central instance can then be used to manage multiple secured OpenShift or Kubernetes clusters.
