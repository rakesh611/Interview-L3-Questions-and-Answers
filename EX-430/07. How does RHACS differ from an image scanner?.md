# How Does RHACS Differ From an Image Scanner?

## Overview

An **image scanner** primarily answers:

> **"Does this container image contain known vulnerabilities?"**

**RHACS (Red Hat Advanced Cluster Security)** goes much further. It provides security across the **entire Kubernetes/OpenShift application lifecycle**, including image vulnerabilities, Kubernetes configuration, access control, network exposure, admission control, and runtime behavior.

A simple way to remember it:

```text
Image Scanner
     │
     ▼
"Is this image vulnerable?"

RHACS
     │
     ├── Is the image vulnerable?
     ├── Is the workload securely configured?
     ├── Is the deployment allowed?
     ├── Is the container running with excessive privileges?
     ├── Is the workload exposed?
     ├── Is the runtime behavior suspicious?
     └── Does the application violate security policies?
```

---

# 1. What Is an Image Scanner?

An image scanner analyzes a container image and identifies known security vulnerabilities.

Example:

```text
registry.example.com/payment:v1
                │
                ▼
          Image Scanner
                │
        ┌───────┴────────┐
        ▼                ▼
     Packages           CVEs
        │                │
        ▼                ▼
   openssl-3.x       CVE-XXXX
   glibc-2.x         CVE-YYYY
   curl-8.x          CVE-ZZZZ
```

The scanner generally compares packages and software components against vulnerability databases.

Example result:

```text
Image:
payment:v1

CRITICAL: 2
HIGH:     7
MEDIUM:   15
LOW:       4
```

The primary focus is:

```text
Container Image
       │
       ▼
Software Components
       │
       ▼
Known Vulnerabilities
```

---

# 2. What Does RHACS Do?

RHACS provides a broader Kubernetes/OpenShift security platform.

It covers multiple security areas:

```text
                    RHACS
                      │
       ┌──────────────┼──────────────┐
       │              │              │
       ▼              ▼              ▼
 Image Security   Deployment      Runtime
                  Security       Security
       │              │              │
       ├──────────────┼──────────────┤
       │              │              │
       ▼              ▼              ▼
 Vulnerabilities   Admission      Runtime
 SBOM              Control        Detection
       │              │              │
       └──────────────┼──────────────┘
                      │
                      ▼
                 Kubernetes
                   Security
```

RHACS therefore goes beyond scanning the image itself.

| Capability                             | Image Scanner | RHACS |
| -------------------------------------- | ------------: | ----: |
| Container image vulnerability scanning |           Yes |   Yes |
| CVE detection                          |           Yes |   Yes |
| Package identification                 |           Yes |   Yes |
| Image risk assessment                  |       Limited |   Yes |
| Kubernetes configuration analysis      |    Usually No |   Yes |
| OpenShift security analysis            |    Usually No |   Yes |
| Kubernetes RBAC analysis               |    Usually No |   Yes |
| Network security analysis              |            No |   Yes |
| Admission control                      |    Usually No |   Yes |
| Runtime security                       |            No |   Yes |
| Runtime process monitoring             |            No |   Yes |
| Runtime network activity               |            No |   Yes |
| Security policies                      |       Limited |   Yes |
| Multi-cluster security                 |       Limited |   Yes |
| Compliance visibility                  |       Limited |   Yes |
| Central security dashboard             |    Usually No |   Yes |
| Risk prioritization                    |       Limited |   Yes |
| Security alerting                      |       Limited |   Yes |

# 4. Image Scanner Example

Suppose you have:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  template:
    spec:
      containers:
      - name: web
        image: nginx:latest
```

An image scanner might report:

```text
nginx:latest

CRITICAL: 1
HIGH:     4
MEDIUM:   8
```

The scanner tells you:

> "This image contains vulnerable components."

But it may not answer:

```text
Is the container running as root?

Does the pod use hostNetwork?

Does the pod have privileged access?

Does the service account have excessive permissions?

Is the application exposed to the Internet?

Does the deployment violate Kubernetes security policies?

What is the container doing at runtime?
```

# 5. RHACS Looks at the Workload

RHACS can evaluate the image together with the Kubernetes/OpenShift deployment.

For example:

```text
Deployment
    │
    ├── Image
    │     ├── CVEs
    │     └── Components
    │
    ├── Security Context
    │     ├── privileged
    │     ├── capabilities
    │     └── root user
    │
    ├── Service Account
    │     └── RBAC permissions
    │
    ├── Network
    │     ├── Services
    │     ├── Routes
    │     └── NetworkPolicies
    │
    └── Runtime
          ├── Processes
          └── Network activity
```

This provides much more context than an image-only scan.

# 7. Image Scanner = Image-Level Security

Think of an image scanner as:

```text
             IMAGE
               │
       ┌───────┴────────┐
       ▼                ▼
   Packages           Libraries
       │                │
       └───────┬────────┘
               ▼
             CVEs
```

The scanner primarily focuses on:

```text
"What is inside this image?"
```

# 8. RHACS = Application/Cluster Security

RHACS considers the larger environment:

```text
                    RHACS
                      │
        ┌─────────────┼─────────────┐
        ▼             ▼             ▼
      Image        Kubernetes     Runtime
      Security     Security       Security
        │             │             │
        ▼             ▼             ▼
      CVEs          RBAC          Processes
      Packages      SCC           Network
      SBOM          Policies      Behavior
                    Secrets*
                    Exposure
```

> `*` RHACS can identify security risks involving secrets/configuration, but it should not be treated as an application secrets-management system.

# 9. RHACS Admission Control

One of the major differences is **admission control**.

An image scanner can identify a vulnerable image.

RHACS can use security policies to prevent a deployment from being admitted.

Example:

```text
Developer
    │
    │ Deploy image
    ▼
OpenShift API
    │
    ▼
RHACS Admission Controller
    │
    ├── Policy PASS
    │       │
    │       ▼
    │    Deployment allowed
    │
    └── Policy FAIL
            │
            ▼
       Deployment rejected
```

Example policy:

```text
Do not deploy an image with:

CRITICAL vulnerability
AND
fix available
```

This turns security from:

```text
Detect → Report
```

into:

```text
Detect → Prevent
```

# 10. Runtime Security

A traditional image scanner normally does not continuously monitor what happens after the container starts.

Example:

```text
Image:
web:v1
```

The image may appear safe during scanning.

After deployment, an attacker could exploit the application and execute:

```text
/bin/bash
```

or:

```text
curl
wget
python
```

or attempt unexpected network communication.

RHACS runtime security can detect suspicious runtime behavior based on its runtime security capabilities and policies.

Conceptually:

```text
Container
    │
    ├── Expected process
    │
    ├── Expected network connection
    │
    └── Unexpected activity
             │
             ▼
        RHACS detection
             │
             ▼
           Alert
```

# 11. Kubernetes Security

An image scanner generally does not understand the complete Kubernetes security posture.

RHACS evaluates Kubernetes/OpenShift security context.

Examples:

```text
Privileged containers
HostNetwork
HostPID
HostIPC
Dangerous capabilities
Root execution
HostPath usage
Service account permissions
RBAC risks
Network exposure
Security policy violations
```

Example:

```yaml
securityContext:
  privileged: true
```

An image scanner may not care because this configuration is **outside the image**.

RHACS can identify this as a workload security risk.

```text

   ▼

   │
   ▼

   ▼
```


Therefore RHACS can answer questions such as:

> "Which vulnerable workloads are exposed externally?"

This is much more valuable than simply knowing which images have CVEs.

# 13. Risk Prioritization

Imagine you have:

```text
100 Critical CVEs
```

An image scanner might report all 100.

RHACS can add environmental context.

For example:

```text
Vulnerable Image
       │
       ├── Production?
       │
       ├── Internet exposed?
       │
       ├── Runs as root?
       │
       ├── Privileged?
       │
       ├── Network reachable?
       │
       └── Active runtime behavior?
```

This helps security teams prioritize the most dangerous workloads.

For example:

```text
Risk #1
Critical CVE
+
Internet exposed
+
Production
+
Privileged container
```

This should normally receive attention before:

```text
Risk #2
Critical CVE
+
Development
+
Not externally exposed
+
No active workload
```

# 16. Where Skopeo Fits

**Skopeo is not itself a full vulnerability scanner.**

It is primarily a tool for working with container images and registries.

For example:

```bash
skopeo inspect docker://registry.example.com/app:v1
```

It can inspect image metadata without necessarily pulling the image in the traditional way.

A vulnerability scanner can then analyze the image.

Conceptually:

```text
Registry
   │
   ▼
Skopeo
   │
   ▼
Image / Metadata
   │
   ▼
Vulnerability Scanner
   │
   ▼
CVE Results
```

RHACS operates at a much broader security layer.

# 18. When Should You Use an Image Scanner?

Use an image scanner when your primary requirement is:

```text
"Find vulnerabilities inside my container images."
```

Typical use cases:

```text
CI/CD vulnerability scanning
Registry scanning
Developer security checks
CVE reporting
Image approval
SBOM generation/analysis
```

---

# 19. When Should You Use RHACS?

Use RHACS when you need broader Kubernetes/OpenShift security.

Typical requirements:

```text
Multi-cluster security
Kubernetes security
OpenShift security
Image vulnerability management
Admission control
Runtime security
RBAC analysis
Network security
Security policies
Risk prioritization
Compliance visibility
Centralized security operations
```

---

# 20. Can RHACS Replace an Image Scanner?

The answer depends on the environment and required workflow.

RHACS includes image vulnerability analysis as part of its security capabilities, so it can provide much more than a standalone image scanner.

However, an enterprise may still use specialized scanners in its CI/CD or registry workflow.

A common architecture can therefore be:

```text
              CI/CD
                │
                ▼
          Image Scanner
                │
                ▼
         Image Registry
                │
                ▼
             RHACS
                │
       ┌────────┼─────────┐
       ▼        ▼         ▼
    Admission Runtime   Risk
    Control   Security  Analysis
```

The tools can complement each other rather than being mutually exclusive.

# 22. Interview Answer

### Question

**How does RHACS differ from an image scanner?**

### Answer

An image scanner primarily scans a container image for known vulnerabilities such as CVEs in operating-system packages and application dependencies.

RHACS provides a much broader Kubernetes/OpenShift security platform. It combines image vulnerability analysis with **Kubernetes configuration security, RBAC analysis, network security, admission control, runtime monitoring, security policies, risk prioritization, alerting, and centralized multi-cluster security management**.

For example, an image scanner can tell me:

```text
payment:v1
CRITICAL CVE: 2
```

RHACS can additionally tell me:

```text
Where is the image deployed?
Which cluster?
Which namespace?
Is it production?
Is it externally exposed?
Does it run as root?
Is it privileged?
Does it have excessive permissions?
Does its runtime behavior violate policy?
Should the deployment be blocked?
```

So:

> **An image scanner answers "Is the image vulnerable?" while RHACS answers "How risky is this workload in its Kubernetes/OpenShift environment, and can I prevent or detect unsafe behavior?"**
